## PRD 1.1 · 2026-09-16 · CR-001：直接复用 DSH 前端 UI

**目标产品仍为 Writing Agent 1.0。本次 1.1 是文档修订号，不是宣布产品 1.1 已发布。**

### 变更原因与已确认方向

用户明确不接受把旧桌面包 0.1.0 作为新版界面利旧方案，希望直接利用 DSH 的前端源码、页面和界面体系，并便于后续调整。该前端来源决定已确定，不再作为等待确认的可选项。

原仓库身份、历史、旧文章、风格、写作方法、核查规则与用户数据仍保留。新产品仍是源码级复用后自主维护的系统，不变成 DSH 的插件、SDK 包装或依赖其服务的客户端。

### 与初稿不同的内容

| 初稿路线，已失效 | PRD 1.1 路线 |
|---|---|
| 借鉴 DSH 有价值的 UI 组件，前端复用旧 React 页面 | DSH 前端源码与可复用页面体系是唯一新 UI 基线，先保留外观与交互，再写作化 |
| 将新 runtime 和 UI 接回已有 Tauri 壳 | 新容器分发同源前端；默认优先评估 DSH Electron 最小壳，不沿用旧 0.1.0 启动链 |
| 后端闭环之后再开始工作台 | M1 runtime 与 UI 移植并行；UI 可先在明确标注的本地 mock 下验证，M2 接真实服务 |
| 前端主要围绕新工作台自行组织 | 沿用 DSH 布局、侧栏、对话、主题、设置和必要 Client/Host 协议，新增写作面板 |
| UI 调整没有独立验收 | 增加来源映射、视觉基线、主题/Slot 扩展、协议重连和独立品牌/端点验收 |
| 22 项任务、30 个验收场景 | 25 项任务、38 个验收场景；WA-023–025 按依赖插入，而不是排在发布之后 |

**决定边界：**用户选择了 DSH UI，不等于已经指定 Electron、包管理器或全部通信实现。文档把 DSH Electron 源码移植列为桌面交付的默认评估方案；实施 M0 若证明其他容器更合适，可以提交 ADR 由维护者批准，但不能退回旧界面，不同时维护两套新 UI/桌面壳。

### 已同步的文件

主 PRD 增加 F14、UI-01–08、NFR-13–14 与 AT-31–38，并修订代码组织、旧资产去向、里程碑和发布门禁。

新增 `docs/implementation/FRONTEND_REUSE_PLAN.md`，规定源码移植、依赖闭包、原版/派生视觉基线、写作面板、主题与品牌、bridge 和桌面安全边界。

`RUNTIME_CONTRACTS.md`、`AGENT_HANDOFF.md`、`BACKLOG.json`、`START_HERE.md`、`SOURCE_BASELINE.md`、`GITHUB_AND_LAUNCH_PLAN.md` 同步更新。任务 ID WA-001–022 保持稳定；WA-011、WA-017 改为新 UI 接入与新壳分发，另加三项任务。

### 已开工 Agent 的处理方式

先保留当前分支、提交和未提交文件，读取本修订，再检查旧计划中涉及页面复用和 Tauri 接回的任务。把与 CR-001 冲突的工作列为待调整，不自动 reset、删除或覆盖。已实现的 runtime、数据迁移、版本与核查逻辑能满足契约就保留，不因 UI 来源改变推倒无关工作。

后续按 WA-001–004 补齐新审计；运行时已有部分不重复造，尽早建立 WA-023 的 DSH UI 源码基线，在 WA-011 接真实服务。

### 验证范围

本次是文档修订与只读源码/官方架构文档核对，未改 GitHub 仓库、未移植应用代码、未生成实际运行截图、未构建安装包、未调用真实模型、未完成人工视觉/可用性验收。

当时文档内部任务依赖、编号、相对链接、代码块和 JSON 由原包 `tools/check_document_pack.py` 检查，原报告已归档。当前检查使用 `tests/check_document_pack.py`。这些检查不等于应用或 UI 已经通过验收。
