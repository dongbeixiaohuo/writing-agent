## 设计与范围

采用独立搜索服务接入，复用现有搜索预算、回退、取消和运行记录；不把写作模型切换为 DeepSeek，也不接管原版 Claude Code Skill 的搜索。保持现有角色和顺序，不删除作者确认，不添加一次额外的 LLM 路由调用。

- DeepSeek Search 固定为 `https://api.deepseek.com/v1/tools/search`，独立 Bearer Key，默认关闭。旧设置不自动启用或读取写作模型的 Key。
- 显式启用后的顺序为 DeepSeek → Parallel → Tavily，只访问已启用的服务；关闭 DeepSeek 时原有顺序不变。
- 每次最多五条摘要，`need_content=false`，归一化为现有来源/摘录格式；不把整页原文或整篇文章发送给搜索。128 Unicode 字符限制明确反馈，不静默截断查询。
- Search/Fetch 各按成功请求收费；本次只接 Search，网页读取沿用已有安全读取器，不借搜索开关默许额外付费 Fetch。连接测试使用固定公开问题，并明确消耗一次搜索请求。
- 凭据只进系统/会话凭据库；两个 Key 的更新和配置文件提交需统一回滚。保存不等于验证，配置变化和重启撤销可用标记。
- 所有测试使用 synthetic provider/transport 和隔离临时数据。不读取用户数据库/密钥，不执行新付费服务实测。用户随后明确授权先提交、再打包本地 RC88；该授权不包含推送、创建 Release 或替换公开安装包。

备选方案：将搜索绑到当前写作模型会排除使用 MiniMax 等模型的用户；默认更换现有服务会改变用户的费用与网络选择，因此不采用。

## 可复现的流程审查项

1. Runtime 已有限制失败、格式纠正和总预算，但相同成功读取/ready 仍可反复消耗模型请求；新增保守的无进展纠正/暂停，不能把正常逐段读取或正文变化误判为循环。
2. 模型服务返回超长 Retry-After 时，现有等待可能持续小时或整数溢出；超出可交互等待时应可恢复暂停并解释，不提前重试轰击服务。
3. 同一 run 成功读取同 URL 没有缓存；增加有界缓存，取消、服务关闭和来源授权检查仍优先。跨 run 不复用旧正文。
4. pending-handoff 的暂时配置失败可能被扫描水位缓存吞掉；测试同 service 能力恢复后可重扫，不改成自动无限重试模型。
5. 研究/终审的独立额度和已有 extract/verify 上下文压缩继续保留；仅在可证明来源和快照边界可靠时复用，不能为省请求绕过事实回执要求。

## 当前流程及恢复行为

确认方向 → 研究与证据（可选补查）→ 提纲 → 初稿 → 编辑/发布/模拟读者审校 → 集中修订 → 语言终审 → 选定标题 → 轻量事实核查 → 导出。共创模式的阶段作者确认保持；配图与分发文案仍非必选。不以跳过确认、删掉核查或自动选择标题来换速度。

- 搜索设置新增独立 DeepSeek 开关与密码框。默认关闭；填写并显式保存/验证才请求服务，写作模型可以继续用 MiniMax 等供应商。标记只代表当前启动中实际成功的验证，不把有 Key 当作可用。
- 研究补查仍最多两次，失败使用已有材料继续并保留缺口；最终事实核查仍默认六次，可在设置选 1—30 次，用户决定是否追加或停止。各阶段不为引用或完整论文证明强制搜索所有普通背景。
- 事实核查先提取当前成稿中的关键/可疑事实，验证阶段用条目、必要证据和摘要；不新增原稿全文或整个工具历史的重复注入。DeepSeek 只接收一个短公开问题、返回最多五条摘录，不能将摘录冒充原文已读。
- 同一读取的调用编号、来源目录条数不是业务进展。新增稳定任务键去除这类噪声，但保留任务要求、阶段、版本和真实读取结果。正常分页、保存和角色交接继续运行。
- 同状态第三次重复读取会暂停为 `TOOL_NO_PROGRESS`。点击重试恢复原专家，不重开整篇流程；只是防空转，不承诺模型下一次一定正确。
- `Retry-After` 超过 30 秒或不合法时为 `PROVIDER_RETRY_DEFERRED`，不挂着数小时。有效建议时间会显示为本机日期时间；同服务/模型在到期前点击恢复不会发新模型请求。没有自动恢复定时器，需用户主动重试或切换其他模型。
