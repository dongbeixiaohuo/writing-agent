# 内置文风试写：瘦仙人 / 胖仙人

本轮提供两个候选供用户同题试写，尚未选定默认项，不自动改变项目已有选择。

## 配置与区别

配置源为 `packages/writing-core/src/builtin-styles.json`，每项包括稳定 ID、版本、核心卡、摘要、设计样文、写法和示例片段。通过静态 JSON 导入进入桌面主进程构建，每次正常打包都会包含，不依赖开发机文件或用户手工导入。

- 瘦仙人：清醒有判断。切口小、推进紧凑、短中句为主，事实与解释紧密衔接，结尾判断明确。
- 胖仙人：通透有共鸣。细节更充分、中长句承载观察、叙述舒展，从处境推到理解，结尾有回响。
- 共性：事实边界、读者意识、明确主线、具体表达；不规定固定篇幅、段数、反转次数，也不承诺热度。

样文是原创设计示例，明确标注假设情境，不能作为新文章的事实来源或真实传播效果证据。样文统计由程序计算；没有执行样文提取调用，`modelRequests`、`analyzedCharacters` 为 0。

## 加载与用户数据

风格库在读取时合并内置配置和个人风格，不向数据库播种，不覆盖个人数据。内置项不占 50 个个人风格名额，可直接选用、试写；编辑后另存为个人副本。原有风格卡和项目快照继续兼容。

修改内置定义后应递增该项 `version` 并更新 `updatedAt`，重新构建。已选项目保留自己的版本快照；新项目或重新选择时使用新版本。确定最终默认风格后，另行落实默认选择行为；本轮仍保留“不指定风格”。

## 用户对照方式

使用本次构建的 App，在两个新项目中分别选择“瘦仙人”和“胖仙人”，输入同一选题、读者、篇幅和材料，保持相同模型与写作模式。不在已有文章上切换风格后续写，以免前稿影响比较。已有调研流程照常工作；若比较纯表达，给两组同一份事实材料。

主要比较阅读意愿、洞察是否成立、是否有共鸣、是否愿意转发、是否有成熟作者感。工程检查验证加载和选择链路，成文效果由实际试写判断。
