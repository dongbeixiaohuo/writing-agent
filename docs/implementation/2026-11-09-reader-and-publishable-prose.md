# RC98：读者反馈与可交付正文

## 问题与处理

模拟读者 C 已返回完整 JSON，但复述文章的“68%、24%”触发了笼统词语过滤，被显示成“未返回”。读者响应现在只按五个必要字段、类型、非空与长度验证，不因引用百分比或编辑术语丢弃整份回复。角色提示继续禁止编造传播指标、冒充真实调研或给出编辑清单。实际未完成与无法使用的反馈有独立的人类提示，不输出重试策略、错误代码或“没有编造”等工作说明；失败不冒充成功，不增加自动付费重试。

写作问题不只来自风格卡。需求整理把“明确标注假设”传入提纲，初稿写出工作性括注，编辑又把它评为优点。修改覆盖需求整理、提纲、主笔、编辑、发布审校、修订及语言润色：

- 用自然条件句表达假设，来源类型留在内部记录；主笔不把论证步骤、自我免责、改动清单写进正文。
- 审校优先检验材料是否支持结论、例子是否成立、段落是否带来新理解，再看风格与节奏。明确检查写法自述、重复真假标签和机械循环，不把免责声明列为优点。
- 自动风格观察按用途选用，不升级为每节重复的结构配额；完整指南及例子保留。作者明确指定的结构仍受尊重。
- 润色交接增加与源稿一起传递的语义约束，分别说明要清除的工作汇报、要保留的假设语气、事实限定、引文与必要注释，以及只润色而不重新执行风格卡起草动作的范围。

没有新增按词语自动删稿的规则，也不移除事实限定来营造确定语气。不修改历史稿件、标题、风格数据或已保存的读者报告；更改用于后续生成与审校。

- 读者与并行工作流 20/20，通过真实失败样式的 JSON 及百分比引用，覆盖汇总、保存、恢复、取消和全失败。
- 协作与专家指令 119/119；后续润色交接定向检查 3/3，验证约束进入真实工作流请求。
- 风格检查 46/46；Web、runtime、Desktop 类型检查通过。
- 受控真实模型验证使用独立虚构样稿，不保存到用户工作区。共 5 轮、15 次请求：前四轮暴露了去标签后丢失假设语气或保留论证自述的问题，最终增加源稿旁的语义约束；最后一轮三种场景通过。分别验证清理工作备注、保留有意义的引文与注释、审校发现逻辑与案例问题。它不是同选题完整写作质量或跨模型稳定性验收。
