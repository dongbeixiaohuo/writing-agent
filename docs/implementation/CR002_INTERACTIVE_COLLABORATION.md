# CR-002：恢复导演编排与交互式写作验收

日期：2026-09-19。状态：实施中，产品主流程不具备最终用户验收就绪条件。

本补充是 PRD F01/F02、运行时契约和 WA-010 的强制验收约束；冲突时以本补充为准。CR-001 的 DSH 前端来源决定不变。旧测试、安装包和历史记录保留，但不再以它们证明核心合作能力已完成。

## 1. 偏差与证据

原需求已包含原项目能力迁移、重要缺口追问、读写角色边界和共创模式，并非允许改造成一键流水线；但 F02 的验收只覆盖工具循环/预算，没有约束导演决策、隔离评审和暂停恢复。WA-010 的完成条件进一步缩成材料到稿件保存。实现把角色当成阶段标签、同一会话串行执行，把工具完成误作业务完成。先前宣布最终用户验收就绪不成立。

用户 `test` 项目的只读事件审计：材料仅为 `test`，运行 `7760f4bb-bf4e-4a01-a8b2-418081ef90e2` 在约 33 秒内结束，没有 `run.waiting_user`；研究已经发现材料不足，仍继续产出正文，最后事实门禁 blocked。不得修改该真实库来伪造修复证据。

## 2. 必须实现的业务合同

1. **导演负责决策**：读取已确认简报、材料、用户答复和当前版本，判断下一项任务/缺口/返工/等待/可交付。每次决策保存输入版本、理由摘要、委派角色、任务范围和预期产物；不是给固定阶段循环换角色名称，也不展示模型私有推理。
2. **实际委派与隔离**：研究、主笔、编辑、读者、发布评审有独立的任务上下文与工具权限。可串行，不要求并发或多个供应商；评审绑定同一正文版本，初次评审不得看到其他评审意见，评审不能直接写正文。导演汇总分歧，由主笔集中修订。
3. **必要信息前置沟通**：进入每个阶段前，导演结合已确认要求、最新材料及上一阶段成果重新核对。确实依赖作者的信息未齐时，保存 1–2 个聚焦问题并转入 `waiting_user`，在主对话持续交流，直到足够才推进；不得先跑完再通知作者“前面缺材料”。不能伪造占位正文或显示“全部完成”。Agent 自行引入的无来源细节、误引或核查误判先交导演安排内部修订/复核，不自动成为作者补料任务；涉及作者独有事实或重大取舍才提问。无外部事实文章及不冒充原句的普通比喻不因缺少事实来源而被禁止。
4. **回答驱动恢复**：问题及答复持久化到同一项目/会话/run；重启后可恢复。答复作为用户提供的信息，不能自动标成已核实证据。空回复/单纯“继续”不能解除信息缺口；模型重新判断仍不足时继续追问，已有完成产物不重复写。
5. **确认与自主不同**：共创模式在方向、大纲和影响内容的重要选择处等待意见；自主模式可跳过非必要确认，不能跳过缺口、授权或事实门禁。旧项目的 autonomous 不等于允许忽略问题；迁移不能静默改用户偏好。
6. **主对话承载业务**：当前问题、阶段成果和修改选择在最新消息位置直接显示；可从主输入框答复。运行日志供追溯，“稿件与版本”供历史/精调，均不得成为普通用户发现阻断的唯一入口。
7. **完成语义分离**：步骤已保存、等待用户、运行结束、可正式交付是不同状态。blocked/stale/failed 均不能称作整篇完成；进度不得用全部工具打勾掩盖待处理问题。保留工作稿，不放宽既有正式导出门禁。

## 3. 运行时增补

2026-09-19 权限澄清：三个 `review_editor/review_publish/review_reader` 是只读独立初审，绝不能写正文。`language_review` 对应迁移源 `claude-runtime/agents/humanizer.md` 的 Stage 10，是主笔权限下的末段最小语言润色，不是第四位只读评审，也不是第二轮重大集中修订。它只提交完整文章（无修改时保留原稿），保留标题、观点、结构和事实；需要实质变化时交导演决定是否返工，绝不能把审校报告替换为正文。写作计划元数据、实际权限、提示词及测试必须一致。

- 写作工具提交和导演分派前必须有当前阶段、当前输入版本的 readiness 判断；阶段保存、返工、简报/正文/标题/证据/授权材料版本变化使旧判断失效。判断包含 `ready | needs_input`、理由、最多两条问题。缓存的完整同版本材料及已注入的阶段产物可直接使用，恢复入口仍须读入必需上下文，不因角色切换重复读取。
- `needs_input` 的工具结果携带 `awaitingUserInput`，Runtime 持久化 `run.waiting_user`，`stopReason=WRITING_INPUT_REQUIRED`，保存问题/原因/下一阶段；同一个模型响应中排在它后面的工具也不能执行。
- 持久的 `run.resumed.displayInstruction` 保存答复；恢复提示同时重建本 run 首个 `run.started.displayInstruction` 的初始目标、此前问题与答复，明确数据信任边界；答复不是授权扩大或事实核查通过证明，不能用最新答复覆盖原始修改目标。
- 新执行段重新读取必要材料/现稿与恢复产物，再重新判定 readiness；不能用上一执行段的“已读”标记替代当前模型上下文。特别是现稿修改在 research 前提问后恢复，现稿仍须读入。之后任意阶段仍可提出新问题。幂等重试不得产生重复问题/产物，项目隔离、权限、取消和预算继续生效。
- 现稿续写所绑定的正文版本必须在运行开始时即持久化，不能等到首次提问才记录；首次模型响应或首次等待前崩溃后，恢复仍须读取同一基线。仅成功提交新 draft 后解除旧基线。
- 以上只是交互基础，不代表独立导演/专家合作已实现。后续 task dispatch 记录必须可证明真正独立调用及权限隔离。

2026-09-24 rc.31 收口：`submit_fact_check` 未通过仅保存专家反馈并交还导演，不直接制造 `WRITING_INPUT_REQUIRED`。导演决定内部返工、独立复核或真正需要作者答复的问题；可选润色不能升级为必答事项。事实门禁和版本绑定不放宽。`director_decide(finish)` 仅在所有阶段和当前门禁通过时成功，成功持久化后由运行时直接完成，禁止为了收尾再请求模型反复确认。无显式预算的完整写作采用与桌面一致的 64 请求/96 工具保护；显式调用限制、需求讨论及专项核查限制不变。

## 4. 新验收场景（补充原 AT，不替代原 38 项）

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| C02-01 | 旧项目，材料仅 `test`，发送“开始” | 主对话询问实际主题/材料；没有正文、后续阶段或完成声明 |
| C02-02 | 共创/自主两种模式遇到关键缺口 | 均立即等待；模式不能绕过缺口 |
| C02-03 | 等待后退出重开，再从主输入框补充 | 同一 run 恢复，历史问题/答复可读回；不是另起整篇生成 |
| C02-04 | 空回复、仅“继续”、仍不充分的补充 | 保持等待或追问，不把恢复按钮视作补齐事实 |
| C02-05 | 一次模型响应先提问再提交正文 | 正文工具不能执行；直接提交未经过 readiness 也被拒绝 |
| C02-06 | 信息充分的短篇个人观察/无外部事实文章 | 不按长度或零 claims 误阻断；可以正常推进 |
| C02-07 | 研究中途缺口、评审冲突、用户改方向 | 导演选择补问/返工，按版本使受影响产物失效，不机械跑完 |
| C02-08 | 独立评审与集中修订 | 独立请求快照、同一正文版本、互不泄漏评审、权限拒写证据完整 |
| C02-09 | 事实 blocked/stale，或模型报错 | 主对话准确提示未完成事项，不显示“全部完成/可交付” |
| C02-10 | 最终桌面候选 + 真实模型 | 上述代表旅程有录像/截图/持久事件读回；自动测试不替代真实体验 |
| C02-11 | 研究完成后新发现必要信息不足 | 上阶段 ready 不再有效；提问发生在提纲前，没有提纲或正文 |
| C02-12 | 主笔自行加入无依据细节 | 导演安排内部修订并核查新版本，不要求作者替 Agent 提供证据 |
| C02-13 | 现代比喻被当作事实问题 | 独立复核区分事实与修辞；真实引文仍核查，不直接改状态放行 |
| C02-14 | 导演已结束但模型倾向反复调用工具 | 持久结束后不再请求模型；仅一个 run.completed，未通过门禁仍不得结束 |

就绪标准：C02 全部满足、有真实模型和桌面证据、无核心 P0 缺口，方可重新申请最终用户验收；用户签收与发布门禁仍单独执行。

## 5. 实施顺序与责任

- R1：结构化 readiness/缺口提问/暂停/同 run 回答恢复/主对话展示，先红测试再实现。
- R2：导演与独立专家任务编排、权限隔离、决策及任务证据；不是阶段重命名。
- R3：返工/产物失效/评审冲突/事实阻断与完成语义收口。
- R4：真实模型代表性用例、桌面端到端、安装候选、文档状态与验收证据复核。

R1 完成不等于 WA-010 完成，R4 前不产出“最终用户验收就绪”结论。安装包 rc.6 仍只是历史测试候选。
