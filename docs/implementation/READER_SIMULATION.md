# 三个并行模拟读者

2026-10-08 的桌面工作流修订，覆盖旧 `review_reader` 的单人编辑式诊断设计。不改变原版 Claude Code Skill、编辑审校、发布审校或事实核查合同。

## 产品边界

程序固定三个身份：匆忙路人（低耐心、不了解行业）、目标读者（中等耐心、日常经验）、懂行读者（较真、有专业背景）。阅读场景使用本篇实际平台，不假装读过作者上一篇文章。

每人只看同一完整正文、自己的身份与当前标题/可选配文。五项输出是为什么点开、哪里想划走、读完感受、转发收藏意愿、最记得的一句；允许负面口语和“没有”，不要求编辑报告、修改建议、字数统计或指标预测。

反馈明确是模拟，不能升级为真实用户调研、`reader_feedback` 或用户偏好。程序按身份拼接，不额外调用模型汇总、不投票。共创模式仍是一份阶段成果、一次作者确认；自主模式不要求这次确认。

确认后沿用已有导演请求，`reason` 明确标注“导演解读（非读者原话）”，结合正文位置、写作目标和作者取舍转为修订任务或说明保留理由。不得自动采纳最激烈反应，也不把模拟意见变成作者命令。

## 执行与恢复

- 同一个父 run 内并发三个无工具文本请求，独立上下文、独立信号；不另开三条写作流程。三个请求及用量均计入父预算，先校验全批请求及一次保存的额度。
- 每人最多等待 90 秒，输出上限 2,048 token（仍受用户较低上限约束）。不自动重试；成功者可用，失败者如实标注未返回。全部失败时不保存空报告，暂停并保留当前任务，只有用户明确重试才重新请求。
- 输入快照、请求时序、错误和完成文本正常落库；批次绑定任务、正文、身份、模型和参数。重启后复用同批成功回执，旧版本或改动后的参数不冒用。
- 停止传播给全部请求，迟到回复不能保存；并发期间手改正文，旧反馈不能通过原有版本检查。
- 进度显示三个身份的完成/未返回状态，不展示内部 JSON 或私有推理。运行记录保留各自请求；阶段耗时取并发活动区间并集，不把三人的耗时相加。

## 验证入口

`npm run test:reader` 检查请求并发、隔离、部分失败、全失败、预算、停止、重启回执复用、正文并发编辑和单检查点。`npm run check:runtime` 包含该项；进度与时序还由 `test:conversation`、`test:bridge` 覆盖。

这些是确定性合成模型测试，不证明真实供应商的语义质量、限流情况或实际耗时。三个请求增加两次模型调用，目标是相互独立且同时阅读，不承诺耗时一定下降为某个比例。
