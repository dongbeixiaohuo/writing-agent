# 桌面风格库与轻量提取

日期：2026-10-30。范围：RC89 后当前源码新增功能；不是已发布安装包或旧 Claude Code Skill 的验收声明。

## 使用流程

1. 左侧“风格库”新建名称，添加粘贴文字、TXT/MD/Markdown/DOCX 文档或公开 HTTP(S) 链接。支持一次多选文档、一次粘贴多个公众号/网页链接（每行一个，也支持空白分隔）。公众号复用既有正文提取，不绕过登录、验证或访问限制。
2. 点击“提取风格”，查看规则及样文原句，修改精简风格卡后明确保存。可选输入新主题生成短试写；试写不写入正文，不代表事实稿。
3. 输入框旁“选择风格”将选定版本的精简卡放到本次输入首部；也可在写作方向编辑框中选用。不是全局默认启用，下一篇仍由用户选择。重复选择替换本次旧卡而不丢失草稿文字。
4. 后续需求沟通保留选中卡，确认方向后传给写作角色。引用别人的指令不能自动升级为作者授权；用户改口或取消不能被旧卡覆盖。

## 相比旧方法的调整

- 不要求固定十五维、推断世界观/作者身份、强制三轮盲测或反复模仿。采用一次请求提取 5–8 条有原句支持的可观察写法；证据不足如实提示，不凑数。旧 Skill 文件未改写；App 的 style_modeler 指令使用轻量方法。
- 单篇可用但标记“单样本观察”；“多样本印证”至少对应两份不同样文的逐字引文。程序验证引文存在，不代表证明模型的文学判断正确。
- 新文章只继承表达技法，不继承样文事实、立场、人物、经历或具体物件；样文内容不能成为执行指令。
- 最多十份样文（文档、网页和粘贴合计），每份十万字符，合计三十万；模型样文包仍最多 24,000 字符，长文均衡选取开头/中段/结尾。显示实际分析量与总量，不冒充读完全文。
- 批量入口先校验剩余名额；链接先去重，文档按所选文件数计。超量整批不开始读取，明确提示减少或分组，不静默截取前十份。分析接口也拒绝十一份及以上样文，并返回可读提示。
- 批量读取最多并行两个，完成后按原顺序列出逐项结果；失败不丢弃同批成功项，重复正文不重复入库。失败链接保留在输入框便于重试，失败文档可重新选择。取消本批不会提交晚到结果，取消前已有样本保留。
- 复用只携带不超过 1,800 字符的风格卡，加身份/版本不超过 2,100 字符；不重复带入原文、证据或分析历史。
- 提取/试写各一次模型请求，整体最多 120 秒，支持取消，不自动重试。MiniMax M3.1 Flash 风格任务在未显式指定 effort 时使用 low，适配三种现有协议，其他模型及已保存的全局配置不变。参数依据 [MiniMax 官方说明](https://platform.minimax.io/docs/guides/text-generation)。

## 存储与边界

工作区数据库 schema 9 的 `style_profiles` 保存样文、规则、卡和版本；桌面既有升级流程先备份，再从 schema 8 升级。编辑校验版本，删除不改变旧稿件的卡快照，只读工作区不可修改。分析不会自动保存；取消、失败和晚到结果不能写入。

文档由原生选择器选取，渲染层不能传任意文件路径；上限 4 MiB，DOCX 只解压有界正文，支持 UTF-8/带 BOM 的 UTF-16 文本。本次不含 PDF、旧 DOC、扫描 OCR 或公众号验证绕过。

## 检查与证据

- `npm run test:style`：提取、预算、引文、取消、持久化/迁移、导入、UI、intake 工具及授权回归；已纳入 `npm run check:runtime`。
- 桌面/web TypeScript；启动迁移、需求沟通、协作及专家指令回归。
- 浏览器隔离测试使用真实 Shell/Dialog 与确定性 host：StrictMode、添加/分析/编辑/保存/选用、HTTP 样文、取消及晚回包、试写。合成测试不代表任意网站可达。
- 真实 MiniMax-M3.1-Flash：两段自造样文共 535 字符，一次分析约 9.3 秒，卡 571 字符；另一次短试写约 4.2 秒。默认 effort 配 1,800/4,096 预算曾截断；风格任务 low 后通过。耗时只适用于本次样例，不是长文或其他服务商承诺。
- 未做新安装包升级验收，未把真实用户样文送模型测试；没有改动用户项目正文。
