# 三组角色模型配置

适用范围：2026-11-06 桌面 RC94 本地测试候选；不表示已公开发布。原版 Claude Code Skill 的模型设置不变。

## 用户入口

设置 → 模型 → 角色模型分配。三组默认均为“跟随默认”，只配置一个模型即可使用；已验证通过的供应商与模型组合可独立分配。选择后自动保存，对所有项目下一次启动或继续任务生效，正在执行时不能更改配置。

| 分组 | 职责 | 界面建议 |
|---|---|---|
| 策划与统筹 | 写作助手、选题、导演、提纲、提取待查事实 | 理解意图、分析和规划能力较强 |
| 写作与表达 | 主笔、集中修订、语言润色、标题、开头、风格提取、细节与共情 | 中文写作和风格表现较好 |
| 审校与辅助 | 资料整理、编辑与发布审校、三个模拟读者、事实核查、配图、偏好整理与复盘 | 阅读准确、响应稳定，兼顾速度和成本 |

不推荐固定品牌或价格档位。提示“不确定时保持默认即可”。实际模型质量和速度须由用户结合自己的文章体验判断，连接验证只验证连通性和必要的工具调用。

## 配置与执行规则

- 供应商卡片选择模型后，可单独“验证连接”，不必切换默认模型。成功结果按模型及其连接配置记录；同一供应商的另一个模型不会自动变成已验证。
- 更改显示名称或增加模型目录保留未变化模型的验证结果；更换 Key、接口、协议或请求配置使相关结果失效。验证失败清除该模型标记。旧版本验证记录仅适用于当时选定的模型。
- 显式分配的模型失效时说明对应分组，提示重新验证或选择，不自动回退到其他模型。默认模型切换仅影响“跟随默认”的组。
- 运行时按本次请求的实际角色选择 provider/model，重试保持同一绑定。三个模拟读者独立并行，使用审校与辅助组。请求快照、运行记录记录实际调用模型。
- 事实提取使用策划与统筹组，搜索核对使用审校与辅助组；这仍是一个事实核查阶段，其耗时包含两部分。搜索服务设置、额度及事实门禁不变。
- 没有增加模型负责分流的调用；未新增逐角色配置、自动升级模型或项目级覆盖。

## 维护与验证入口

分组及角色映射维护源：`packages/client-bridge/src/model-groups.ts`。桌面配置保存在原供应商目录的可选 `modelGroups` 字段中，旧配置缺省为全部跟随默认。

定向回归覆盖 `apps/desktop/test/model-groups.test.ts`、`packages/ui/test/model-groups.test.ts`、运行时角色切换和并行请求快照、事实阶段耗时；纳入 `test:desktop`、`test:ui`、`check:runtime` 和 `test:bridge`。合成模型测试不代表真实供应商的费用、速度或写作质量已验收。
