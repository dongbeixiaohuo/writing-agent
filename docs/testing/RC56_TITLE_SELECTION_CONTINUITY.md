# rc.56 — 明确选题不再被旧讨论及正文版本变化吞掉

## 现场与根因

2026-09-29 00:51，作者直接回复「AI 拉开的不是整体替代，是技能与杠杆的差距」。原项目只读事件/请求快照确认：

1. `interpret_author_reply` 实际识别出了旧候选 4，但将其降级成 `discuss`。原因是完整历史中的旧 A/B、字数及句子讨论干扰了当前标题选择问题，模型把“可能以后改变意见”当成现在不能确认的理由。
2. 通用讨论分支仍暴露 `choose_publication`。模型随后尝试选择，被 `PUBLICATION_CANDIDATES_STALE` 拒绝：候选绑定旧润色正文，作者已接受另一次正文修改。之后模型重拟候选，丢失明确选择的效果。
3. 选择成功后的旧任务恢复路径也依赖旧正文快照。不能仅放宽保存条件，再恢复已经过时的写作任务。
4. 页尾“修改已保存”来自先前接受改稿后的组件本地 notice 未清除，并非这一轮选题又改了正文。

上一版真实验证停在等待选标题，没有覆盖正文编辑之后的标题选择交接；不能据其通过认定本次路径正确。

## 修改契约

- 当前待回答的标题问题、完整候选及本条作者回复构成专门的语义判定上下文，不用全篇稿件与全部旧争论覆盖本轮选择。仍由模型理解语义，不新增确认口令匹配。
- 只有 `select_title` 语义结果允许调用保存标题工具；绑定本条原话、候选批次及候选序号。讨论不能顺带锁定标题。
- 正文修改使核查失效，但不取消作者对当前展示标题的选择。标题及随附分发文案绑定当前正文，核查仍须验证当前正文/标题/文案/证据；未修改正文及开头，没有伪造事实通过。
- 候选批次替换、非法标题、意图解释期间正文并发变化仍拒绝提交，不能把旧序号套到新批次。
- 保存标题后由程序保存简短确认回复并结束该交流，不再额外请模型生成一整段答复。旧写作任务正文快照不适用时，启动当前稿件独立事实核查，再结束旧标题等待；保留审计记录。
- 正文更新后仍显示同一批候选及原序号，说明选定后核查当前稿件。新交流或切换会话清除旧改稿 notice。
