## 真实故障证据

### 润色内容闪现后消失

持久事件显示语言终审保存的是与集中修订相同的正文版本。旧主对话按正文版本 ID 全局去重，导致语言终审的公开输出被消除，只留下“是否认可”的问题。数据并未丢失。

现在按运行、阶段和正文版本联合识别展示记录。同一阶段不重复展示，但不同阶段即使沿用同一正文版本，也保留该阶段需要确认的内容；流式预览与保存后的消息保持一致的展示 ID。

### 事实核查等待超过 500 秒

对应运行约 544 秒，已完成的三次模型请求耗时分别为 194.952、106.213、44.461 秒；首个有效内容分别为 193.406、100.197、35.723 秒。随后事实核查模型请求等待 197.576 秒被用户停止。中间读取和调度工具耗时仅几十至一百多毫秒。

这段事件中没有调用 `search_fact_sources`。本次长等待的证据指向 GLM-5.3-flash 多轮模型响应，而不是 Parallel。不能用搜索超时修复宣称模型首字等待已经解决。

### 停止后要求跳过仍需长时间

对应作者交流用了三次请求：意图识别 26.624 秒、回复生成 140.092 秒、将回复重新交给模型包装保存 16.759 秒，总计约 183.564 秒。缺少明确的暂缓控制意图，同时存在不必要的“复制回复再保存”往返。

## 实现约束

1. **临时预览**：从实际模型请求中提取已提供的稿件、提纲和材料节选，依次展示一次；可公开的任务说明与检索词随数据追加。不伪造模型输出，不展示私有推理原文，模型内部处理只显示活动状态。
2. **最终答复**：公开文本增量进入主对话；最终答复开始后收起临时素材，完整回复由程序保存，不让模型再抄写一次。保存后正文保留。
3. **执行轨迹**：默认按真实时间排列 Agent、模型请求和工具操作，标识任务、执行段、当前活动、输入摘要、结果摘要、首内容时间、总耗时与错误代码。停止的请求不会继续显示“进行中”。旧分段统计仍可展开。
4. **数据边界**：运行记录只投影白名单字段，不展示凭据、完整系统提示词或私有推理；来源链接只展示域名，避免 URL 查询参数泄露。
5. **标题时机**：需求澄清、提纲和正文阶段不主动提供发布标题候选；用户已经提供的标题保留，否则正文使用工作标题。正式候选在后续标题策划阶段处理。
6. **搜索时限**：单次 HTTP 交换默认 8 秒，一次搜索（授权、凭据读取及供应商回退合计）20 秒，来源原文读取整体 20 秒。超时明确记录，不当作核查通过；停止信号传到 HTTPS 请求与响应流。SSRF、DNS、重定向和外发授权限制保留。
7. **暂缓核查**：在已有正文、没有待确认检查点时，明确要求暂缓核查只需一次语义识别，然后由程序保存简短回执；不会继续启动搜索或核查。询问能否跳过、仅停用联网、带修改要求的复合指令不能误当作暂缓。暂缓不会把稿件标记为核查通过。

## 尚不能宣称的结论

- 本次没有重新实测真实 Parallel 网络延迟；搜索超时、取消、回退、响应不结束等行为通过受控测试验证。

- 两项独立实现分别由 `gpt-5.6-sol/high` 子 Agent 完成执行轨迹和搜索时限，主 Agent 负责集成、正文保留、控制路径与验收；选择依据是边界清晰且可分别回归，未重复进行全仓调查。
