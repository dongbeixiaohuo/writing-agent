# RC61：自然确认、持久交接与检查点恢复

## 目标与边界

修复“作者已经明确认可，流程却不推进”及其相关的误推进、重复返工和无回复入口问题。模型判断语义，程序绑定真实消息、版本与等待阶段；文字里说“确认了”不再代替持久状态。

本轮在现有未提交 RC60 修复上继续实施，保留其他工作区改动。不修改真实用户项目，不自动确认其稿件，不提交 commit、不推送、不发布，也不安装到用户正在使用的环境。

## 实施内容

### 1. 语义与权限分开

- 检查点来源绑定由程序使用本轮完整用户消息生成，不再要求模型逐字回显 `sourceQuote`。
- 自然认可仍经语义判断；反对、部分认可、提问不能当作交接许可。
- 认可同时附带保存材料、修改或提问时，先处理未完成要求，不只截取“可以”直接推进。明确的当前阶段修改可进入返工。
- 需求确认轮模型提交了实际修改时保留新方案为待确认，不能确认旧方案并丢弃修改。
- 回执仍校验项目、会话、等待事件、正文和简报版本；无关的后续聊天不使既有回执无声作废。
- 审校讨论允许保存补充材料，但不因此获得正文覆盖权。相同材料重试不重复导入、不无谓刷新简报。

### 2. 已落库的确认可恢复交接

- 四类交接（完整写作、检查点恢复、仅事实核查、标题后继续）从持久化结果还原，使用来源唯一的 `workflow-handoff:<artifactId>` 幂等标识。
- 新 service/bridge 和后续刷新扫描待交接结果，不依赖旧页面的单次 `.then` 回调；切换当前项目不丢失原会话的交接。
- 兼容历史回调时只匹配对应来源、操作后缀和事件顺序，不把其他任务的运行误当作已经交接。
- 本地结果已提交、但进程在运行完成前中断时，可从该结果恢复，不重新请求模型生成同一回复。外部副作用结果未知不自动执行。
- 正文/简报已经发生实际变化时保留明确、可跨重启查看的交接错误，不静默返回，也不错误批准新版本。

### 3. 共创检查点不能被故障绕过

- 所有 7 个阶段的完成标记在下次模型请求前检查是否具有真实认可；补偿“保存结果后、暂停前”崩溃窗口。
- 承接 failed/cancelled 运行的成果不等于承接作者认可。缺认可就回到对应检查点，不越过它写下一个阶段。
- 手工改稿后的明确确认使用新版本，并重建已失效的审校输入；历史审校仅通过严格的来源与版本关系承接。
- 返工指令随成果承接，保留原文；未执行的返工继续执行，已经保存的返工稿等待认可，已认可的返工稿不重复生成。
- 仅事实核查的恢复（包括预算保护后重试）仍然只核查，不重新跑完整写作。

### 4. 可操作的界面与错误

- 对话展示当前会话的等待项，允许对可回答的问题继续输入；检查点有“认可并继续”入口。
- 多个等待项不再在 `sendMessage` 与 `resumeRun` 间递归转发；补材料与阶段认可走不同的明确入口。
- 同项目其他会话正在运行时显示定位入口，避免看不到运行却无法操作。
- 运行期间禁用侧栏中会修改正文/版本的动作，避免并发改稿破坏当前提交基线。
- 确认/恢复错误码通过桌面 RPC 保留可解释文案，不全部退化成 `DESKTOP_COMMAND_FAILED`；私有异常仍不直出。

### 5. 传输与提交结果

- 三种适配器将无终止事件的断流识别为可重试网络错误；真正的非法终态仍拒绝保存。
- reasoning 活动计入连接活跃度，但不向用户泄露内部思考文本，也不当作已保存正文。
- 被要求使用保存工具后只返回道歉文字，不能假装任务完成；有界纠正后给出明确错误，避免无止境请求。

## 真实模型验证

脚本：`tests/ux/confirmation-recovery-real.ts`。使用现有配置的 `MiniMax-M3.1-Flash-Preview`，临时隔离工作区；不打印密钥、不修改现有模型配置。

真实请求只承担意图理解；专家阶段正文和普通讨论使用确定性测试输出。每次作者回复落库后销毁并重建 service/bridge，再检查交接，不能将此描述为全篇真实模型验收。

最终 7 组样例通过：

| 用户回复 | 预期与实际 |
| --- | --- |
| 可以，顺便把这句存为参考材料……先记下来再继续 | 讨论当前要求，不直接交接 |
| 不同意 | 留在当前阶段 |
| 认可第一点，但第二点为什么要改？ | 留在当前阶段讨论 |
| 先别交给下一位，解释一下 | 不交接 |
| 认同 | 提纲 → 初稿 |
| 认可； | 初稿 → 主编审校 |
| 我觉得你说的这些都挺对的，往下做吧 | 主编审校 → 读者审校（当前 quick 模式） |

最终一轮 8 次真实请求，其中一次 `PROVIDER_UNAVAILABLE` / HTTP 529，按现有可重试策略重试成功。隔离数据库只读复核确认该错误；原报告的 `requests` 同时含合成阶段事件，不能把它们全部计作真实模型请求。报告脚本后续改为从 `payload.error.code` 提取错误码。

本地证据：`output/desktop/confirmation-recovery-real.json`。它包含测试内容，不作为公开发行附件。
