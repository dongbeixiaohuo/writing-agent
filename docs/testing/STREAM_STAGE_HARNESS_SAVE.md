## 原因与范围

用户“公众号”之后的实际记录历时约 121 秒、9 次正常请求；前面约 100 秒为研究、准入和调度。历史日志的 contentEvents 包含非公开文本及工具数据，不等于用户看到的文本片段。上一轮单请求复现中，工具参数在一次 delta 返回 4,469 字符，预览一次增加约 4,180 字符。

此前公开阶段提示优先把全文放进 submit_writing_stage，普通文字结束后还可能要求模型重新序列化全文。这不能保证用户可读文字逐步输出。

本次只调整公开阶段（提纲、初稿、三类审校、集中修订、语言终审），不改变研究账本、事实核查、标题选择或需求澄清的业务授权。

## 实现契约

1. application 为独立专家绑定 textOutputTool 的工具名、阶段和 content 字段。模型可见工具与程序保存权限分离：公开阶段不向模型提供全文保存工具，仍可读恢复上下文和通过 needs_input 追问真实缺口。
2. 普通文本增量立即进入原有预览。只有正常 stop 的完整文本才被程序原文交给现有工具管线；不增加第二次模型请求，也不拼接截断片段。
3. 程序保存仍经过工具 schema、权限、预算、任务 scope、准入、阶段顺序、正文版本 CAS、审校绑定和暂停检查。不将预览当保存，不自动确认提纲，不放行事实门禁。
4. 本地保存事件标明 origin=harness_text_output；模型 request.completed 中不伪造模型调用 ID，后续消息不伪造工具对话。
5. 校验失败仍反馈给同一专家；重新生成的文字替换旧预览，不让旧预览挡住修正内容。明显的“正在整理”等纯状态语不能充当阶段成果；短篇第一人称正文不因此被拒绝。
6. ready 绑定当前阶段及材料版本。已经完整读取并注入上下文后不再开放重复 read_material；版本改变则准入失效并重新开放读取。恢复产物读取、真实缺口提问仍保留。
7. 等待提示按真实角色解释研究、核对、核查的目的；不展示私有推理，不模拟进度或打字。
