# 写作方向与无效扩写回归

日期：2026-10-12。适用范围：桌面/Web App 的需求整理、方案保存与独立写作专家提示词。
这是本次修改的验收说明，不是所有历史版本或模型的质量结论。

## 问题与调整

本次样例中，Agent 把“我看见了，我还在里面”解释为多项禁写规则，提纲又要求排除具体事件、对白和全部具体情节。初稿为 1770 字符，审校发现重复后，导演仍要求只扩写念头到约 2500 字，集中修订稿增长到 2495 字符。

调整的不是作者的立场，而是创作决策的边界：

- 区分用户原话、已确认方案与 Agent 推测；一般认可不授权新增禁令。需求聊天和方案保存共用同一套规则。
- 不虚构作者亲历，但允许用户已有判断、清楚的概念区分、可辨认的行为和明确的说明性假设。示例不能冒充作者经历或事实。
- 约字数是目标，不是填满配额。没有新增信息时允许缩短；用户明确的硬性篇幅和取舍仍须尊重。
- 主编与发布审校可以质疑 Agent 的提纲和文风，不能把指代不清或残句评价为高级留白。
- 导演与集中修订不得一边去重复、一边要求用同类念头填字；核心方向需要改变时仍须按现有提纲返工与确认流程处理。

不修改事实核查门禁、模拟读者角色、存储结构或既有用户稿件；不增加模型轮次或新的审校阶段。旧方案不会被自动改写，重新创作时仍需要结合作者当前要求重新审视其约束。

## 自动化验证

新增 6 项回归，先观察失败，再修改并验证通过：

1. 提纲要求信息推进，初稿区分作者判断与虚构亲历。
2. 专业审校允许质疑提纲，模拟读者仍只输出感性反应。
3. 导演和集中修订优先去重复，而不是填满建议字数。
4. 普通需求聊天不从一句自述推导禁令。
5. 实际方案保存请求也包含同一套创作边界。
6. 通过应用运行时检查专家的实际请求：新规则被传入、作者明确约束仍保留、短于建议篇幅的完整正文仍可保存。

## 真实模型质量验收（待执行）

使用同一模型与参数、隔离测试项目，不覆盖原稿。保留各阶段请求、方案、提纲、初稿和修订稿，比较阶段之间的变化，而不是只判断最终稿。

| 样例 | 输入与明确要求 | 检查重点 |
| --- | --- | --- |
| 少量自省观点 | “别为你干的蠢事赋予意义”“人喜欢找理由求自洽”“不停地想，却迈不出一步”“我看见了，我还在里面”；其余授权合理取舍 | 不自动派生禁止希望/解释/全部具体表达的规则；每段有新增理解或有意义的感受变化；不造作者经历；不用重复念头补字数 |
| 明确风格取舍 | 同上，作者明确要求短句、第一人称、不写操作步骤、不作积极结尾 | 保留这些要求；不把优化理解成必须改为故事或教程；指代与末句仍能理解 |
| 明确篇幅冲突 | 同上，作者明确要求不少于 2500 字，但不给具体经历 | 说明有限内容与硬性篇幅的实际冲突，提供能增加理解的展开方向；不能擅自降低要求，也不能拿同义句和虚构亲历填字 |

人工检查：删除某一段后读者是否失去信息或感受推进；隐喻是否有清楚对象；末句能否说明在说什么；修订增加的内容是否真的有收益。抽象、短句、第一人称与留白本身不作为失败条件，也不以某个固定字数或自动评分代替阅读判断。
