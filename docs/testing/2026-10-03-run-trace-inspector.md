# 运行轨迹详情：从统计摘要到可检查的执行记录

## 范围与参考

本轮继续处理 RC62 的反馈：运行记录只有“第几次请求 / 返回几个工具调用 / 请求 ID / 时序”，无法判断 Agent 实际做了什么。

参考 [DeepSeek Harness 的 ui-trajectory](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84/packages/client/ui-trajectory)，采用“持久事件 → 时间顺序列表 → 按需读取所选步骤详情”的方式。参考点包括调用关联、参数与结果分离、历史工具定义、分页和不打断历史阅读的尾随行为；没有引入它的宿主或替换本项目 runtime。

最初完成源码与构建验收后，按用户后续要求生成 RC63 本地测试安装包，打包验收见末节。既有 RC62 安装包仍对应前一轮代码，不包含本次新增的详情面板。未推送、公开发布或修改用户的写作项目、模型配置、搜索配置。

## 用户能看到什么

| 位置 | 内容 |
| --- | --- |
| 轨迹列表 | 专家、阶段/执行段、实际回复节选、工具名称、检索词或操作说明、结果摘要、状态与耗时 |
| 概览 | 当前步骤、关联请求/调用、保存状态和历史缺失说明 |
| 输入 | 当次模型请求保存的消息与参数，或工具的实际参数 |
| 输出 | 当次模型回复、工具调用、用量、错误，或工具实际结果 |
| Schema | 当次请求保存的工具定义，不拿当前工具定义冒充历史定义 |
| 时序 | 响应头、首个有效内容、最后内容、总耗时及当前活动 |

“首个有效内容”不等于“首个可见正文”。内部处理只有活动状态，不展示私有推理。没有记录的字段明确提示缺失，不伪造历史。

列表默认最近 60 条，可加载更早记录；搜索针对已投影的摘要，不声称搜索全部原始输入/输出。详情仅在点击步骤后读取。上翻时不被新步骤拉回底部，可点击“回到最新步骤”恢复尾随。

## 实现与安全边界

- `WritingApplicationService.getRunTraceSource` 按项目、会话、运行、事件范围检查权限，只读取对应运行事件与一个关联请求快照，不写入项目。
- 请求快照选择当前步骤之前最近的一次准备事件；工具通过请求 ID 和实际返回的调用 ID 关联，避免同一请求重试后把工具错配给失败尝试。
- 新桥接能力 `run.trace-detail`，协议版本 21；桌面 RPC 和本地 Web 均接通。详情响应不携带全量界面快照，不触发主界面快照替换。
- 常规快照只带摘要，完整消息、参数、结果和工具定义通过按需详情接口读取。
- 详情进行常见密钥、认证头、敏感查询参数、本机路径、续传数据和私有推理字段脱敏；包含 JSON 字符串的工具结果也递归处理。列表摘要同时过滤常见密钥。
- 每个详情区最多展示 64,000 字符，并标注原长度和截断状态；原始 SQLite 记录不变。
- 这是本机调试查看，不是公开诊断包。输入仍可能包含用户文章与材料；脱敏是尽力防护，不构成安全公开分享保证。前一轮文档中“不展示完整系统提示词”的摘要限制不等于本次按需本地输入详情的限制。
- 快速切换步骤时丢弃旧读取结果；运行中的选中步骤完成后只补读一次。定时器、主输入框编辑和普通新步骤追加不会反复读取详情。
