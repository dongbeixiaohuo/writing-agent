# RC100：写前切口与材料适配验证

本轮针对“材料已经否定了原题，流程仍照原题写出考证报告”的问题。验收分开看：能否在初稿前退回不成立的承诺，以及作者另选切口后能否写出具体、有推进的文章。不把程序通过当作热文效果证明。

## 实现范围

- 沿用原研究、提纲、写作、审校角色。提纲编辑在同一次请求中判断题目承诺、核心前提、读者所得与段落新增信息，没有增加专家或固定评审轮次。
- 提纲直接读取作者原话、最新回复与绑定的来源引文，不继承研究者的成文结构、导演的扩写指令。对话助手生成的方案约束不冒充作者原话；手工保存的明确约束继续传递。
- `ready`、`research`、`discuss` 是程序可区分的结果。缺核心前提不保存提纲；只能补查或讨论新切口。搜索不可用、额度耗尽或需要作者改变方向时，不空转研究。沿用全任务最多两次背景搜索及既有返工预算。
- 程序核对引用编号、实际引文、未解决前提和提纲章节，并绑定研究完成记录、需求版本与提纲版本。语义判断仍由模型承担，引用存在不等于论证正确。
- 写作接收通过判断的承诺、章节与选定材料；旧选材说明和研究备注不进入默认写作上下文。保留真正的来源归属、时点与限制，不靠删限定获得流畅。
- 内部评估独立保存，不流入正文或流式预览。供应商附加的非契约元数据（实测出现 `stage_note`）会丢弃；必需决策字段继续严格校验，不为无关备注重付一次请求。
- 相同材料经过返工也能形成新的完成记录，不会复用已失效的标记反复重跑。“认可继续”只允许再次判断，不等于补足证据；相同的否决结果在重启和回复后仍然有效。
- 仅新研究完成记录启用该机制，旧任务可继续；没有批量修改已保存文章、标题、模型配置或风格库。
- 修订与终审沿用已有 JSON 正文提交通道，由程序绑定阶段并执行同样的逐项校验。实测当前模型在强制工具调用中反复返回占位编号，改用该通道后能保存完整结果；没有放宽问题编号、引句、版本或返工校验。

## 胡雪岩与马斯克同题试验

试验读取原工作区，所有写入均在 `output/quality/rc100/` 的独立副本。保留原选定的“瘦仙人”风格；没有改写人工原稿来冒充模型改善。

| 试验 | 实际模型请求 | 观察与判定 |
|---|---:|---|
| `frozen-1` | 2 | 初版仍携带旧方案约束，模型尝试写回证据分层文章，并出现无效 JSON；到试验时间上限终止，没有保存提纲或正文。失败。 |
| `frozen-2` | 3 | 移除助手方案污染后，同批材料明确无法支撑“私生活服务财富与影响力布局”；回到讨论切口，保存正文数为 0。原题阻断通过。额外元数据引发的格式重试随后已按上述规则处理。 |
| `reframed-1` | 7 | 模拟作者改选“笔记怎样描绘大家庭、公开话语怎样谈生育”。初稿开始比较具体措辞，但仍有整段材料说明，并把不同年份数字读成矛盾。测试输入还遗漏了旧材料的时间背景。这版不作为成文改善通过依据。 |
| `reframed-2` | 5，另有 2 次背景搜索 | 保留完整时间背景，使用 App 已启用的搜索服务补查。正文以笔记中的分队棋局与公开生育表态展开，舍弃旧数字的假冲突，不再以证据等级组织全文。初稿仍有“总是”“每次”之类泛化与重复边界说明，继续交现有冷读、修订和终审验证。 |
| `reviewed-2` | 11 | 延续上述初稿，独立审校指出人物动机、媒体归因和泛化问题；原工具通道连续返回占位编号，被校验拦下，无修订稿保存。失败记录保留。 |
| `reviewed-3` | 0 | 测试脚本恢复时漏做既有输入就绪检查，未调用真实模型。修正脚本后从原失败副本继续。 |
| `reviewed-4` | 3 | 修订改走 JSON 通道后保存新稿，纠正把公开人口主张直接归为个人生育动机等问题。试验次数上限在终审发送前触发，未向服务商发出该次请求。 |
| `reviewed-5` | 3 | 原终审工具通道也返回占位编号，被严格校验拒绝，无新正文保存。 |
| `reviewed-6` | 1 | 终审改用已有 JSON 提交通道后完成一次真实核对，到达终审确认处，未执行事实核查或发布。 |

原题阻断测试只调用真实提纲模型，其研究输入是原任务的冻结记录；改切口试验调用真实研究、提纲与初稿模型。导演调度与作者确认由脚本完成，新切口是隔离试验中的模拟选择，不声称真实用户已经选定。

实测路由：研究为 `bailian-token-plan/deepseek-v4.1-flash-1017`，提纲为 `glm-5.3-flash`，初稿为 `deepseek-flash`，均读取当前配置，未写入个人模型设置。补查试验使用当前已启用的 DeepSeek 搜索，两次额度没有扩充。

结果边界：本题已验证的关键改善是原题材料不足时不再硬写，改切口后会用具体材料推进，并能纠正部分过度推断。最终试稿仍偏说明性，终审还保留了开头“这篇只比较……”的范围说明，不能把模型终审通过等同于可读性或全部工作备注问题已解决，更不作为“已写出热文”的证明。原用户尚未选择模拟的新切口；升级后应由用户实际讨论决定。没有人工改写试验文章来提高结果。

## 可复现入口与回归

`tests/ux/rc100-prewriting-live.ts` 是显式启动、限次数的真实模型试验，不进入自动 CI。设置 `WRITING_AGENT_COMPARE_WORKSPACE`、`WRITING_AGENT_COMPARE_PROJECT` 后运行：

```text
node --import tsx tests/ux/rc100-prewriting-live.ts frozen <新输出目录>
node --import tsx tests/ux/rc100-prewriting-live.ts reframed <新输出目录> <模拟作者切口文本>
node --import tsx tests/ux/rc100-prewriting-live.ts reviewed <新输出目录> <已生成初稿的试验目录>
```

`reframed` 设置 `WRITING_AGENT_COMPARE_SEARCH=1` 才使用当前配置的搜索服务；不修改配置。`reviewed` 复制试验工作区，继续既有审校阶段，停在语言终审确认处，不执行发布。`WRITING_AGENT_COMPARE_CAP` 可显式限定本次真实请求数（1–14），副本记录继承路径和历史计数，不清除失败。目录必须不存在；产物与请求记录不提交源码库。

回归覆盖：缺前提拒绝成文、非法引用、说明性材料不能作来源、个人表达可写、版本绑定失效、补查与讨论分流、无搜索时不浪费返工、无变化补查、回复后重复否决、重启恢复、旧任务兼容、作者原话隔离、明确手工约束保留、隐藏内部评估及实际 CLI 演示。

本地完整 `check:runtime`、`check:ui`、`check:desktop` 已通过；新增兼容与元数据用例单独复核。原工作区 34 个正文和标题版本的 SHA256 与修改前一致，供应商配置 SHA256 一致。没有平台发布数据、用户盲评或热文概率结论。
