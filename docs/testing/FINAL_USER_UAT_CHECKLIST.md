## 2. 必做验收旅程

请使用一组可公开或专门准备的测试材料，不要把客户敏感资料用于首次验收。

1. 如果已经安装 rc.1–rc.5，先关闭 Writing Agent，不要手工卸载，直接运行 rc.6 安装包。确认升级后必须先看到“步骤 1/2：正在移除旧版本”，成功后再看到“步骤 2/2：正在安装 Writing Agent 1.0.0-rc.6”；不能只在后台删除而没有反馈。旧卸载登记缺失时还应看到“旧安装记录不完整”。完成后确认 Windows“已安装的应用”只剩一个 Writing Agent、版本为 rc.6，原项目和模型设置仍在；全新安装则确认首页显示“本地保存已就绪”，且没有命令行窗口。
2. 在“设置 → 模型”填写已授权配置，点击“保存并验证连接”；必须明确显示鉴权、模型、流式响应和工具调用均可用。
3. 新建项目。界面应按“选题策划 → 读者研究 → 创作导演 → 资料研究”逐步提问，而不是一次展示巨大表单；默认 Deep + 逐步共创，添加至少两份材料后复核简报。
4. 点击此前已存在但没有任何会话的旧项目 `test`。它必须立即成为“当前项目”，主区显示“在‘test’中开始新对话”和可用输入框，不能报“没有可恢复会话”或继续停留在上一个项目；发送第一条消息后，会话必须创建在 `test` 下。
5. 至少再准备一个有历史会话的项目。点击它时必须恢复该项目当前/可继续/最新会话；左侧同时清晰显示“当前项目”和“正在查看”。再点击左上“新建对话”，主区应回到该项目的新对话状态，而不是偷偷继续旧会话。
6. 发送写作要求。发送后应立即看到用户消息和当前阶段，页面自动跟随最新内容；主动上滑阅读时不能被强制拉回。
7. 提纲完成后，检查点必须在主对话自动展开，正确渲染标题/列表/粗体，不显示 `##`、`**` 等原始 Markdown；同时显示角色、下一步和可输入的修改意见。
8. 输入一条具体的提纲意见后继续，后续初稿应能体现该意见；初稿与读者审校检查点再重复一次“查看成果 → 输入反馈 → 带意见继续”，不能只有无语义的继续按钮。
9. 运行完成时，完整稿件应直接出现在主对话。再发送“压缩到 3000 字左右，保留结尾”；运行记录必须先出现读取当前正文，结果是基于现稿修改而不是另起一篇。
10. 若事实状态为 blocked/stale/错误，主对话必须突出显示具体主张、建议动作和“查看并处理”；不允许只在“稿件与版本”内才能发现。按该入口应直接打开“核查与来源”。
11. 在“稿件与版本”做追溯/精调检查：正文、材料与过程、三类审校、版本历史、核查与来源均有真实内容，没有裸 JSON 或仅显示内部 UUID。
12. 对一个正文块执行“局部修改 → 差异预览 → 接受”；旧核查必须立即变成 stale。
13. 点击“重新核查当前稿件”。只有当前快照 passed 后，正式 TXT/HTML 才能导出。
14. 分别选择“清爽阅读 / 杂志长文 / 紧凑报告”导出 HTML；至少抽查两种文件，确认视觉样式确实不同，且都只有正式正文，没有审校意见、工具日志、“正文如下”或版本 ID。
15. 关闭并重新打开应用，确认项目、简报、正文、版本、核查状态和导出记录仍在。

## 3. 数据安全验收

- 创建工作区备份，确认界面显示文件名、大小、schema 和 SHA-256 摘要。
- 在一次性测试项目上点击左侧垃圾桶入口。确认框必须列明将删除材料、对话、草稿、版本、事实核查和运行记录；错误名称时按钮保持禁用，输入完整项目名后才可删除。删除后其他项目必须保留；不要在正式数据上试删。
- 整库恢复会替换而非合并当前工作区。只在一次性测试工作区中执行：先选择备份并检查，再输入“恢复工作区”，确认程序重启、项目读回且恢复前安全副本存在。
- 模型 Key 不应出现在项目、诊断包、日志、截图或备份说明中。
