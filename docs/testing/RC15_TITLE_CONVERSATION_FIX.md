# rc.15 标题交流与旧检查点恢复

日期：2026-09-21。范围：用户反馈的“正文开场被当成标题、反对意见无法继续”。本次只恢复这一环节的桌面复测，不将工程通过升级为完整写作或最终业务验收通过。

## 现场与根因

只读检查用户指定工作区中的运行 `aa179569-9f06-4f67-bd0f-c28f86ea8ce3`。它于 2026-09-21 01:57（北京时间）停在标题选择，标题版本为空。候选报告 `49433317-e2cd-4ca8-b333-6bd083f7ec26` 只有 1 项，内容是正文首段，而不是三个标题。对应正文 `d6606880-d2fb-4ae8-a53e-ef8a3b1e8dec` 没有标题 heading。

1. 共创流程在没有独立标题时用正文第一行兜底，错误地把场景段落当成可确认标题。
2. 卡片走 resumeRun，主输入框走 sendMessage，两条路径对标题讨论处理不一致。没有明确选择时，意见应成为独立作者交流回合，不能恢复后续核查。
3. 旧等待事件的问题固定在历史里，即使重新生成候选，界面也可能仍呈现旧问题。当前卡片应投影绑定当前正文的最新持久候选。
4. 真实重放发现“只讨论标题，正文不要改”会关闭候选持久化契约，导致模型只在回复中列出标题、没有保存新候选。这是第二个经真实模型发现并修复的问题。

截图中的长意见能通过已有“有实质答复”检查，现场未持久化这条意见或恢复事件，故不能断言截图红字就是长文本被正则拒绝。红字也可能是此前提交的局部残留；本次清除输入修改后的旧错误，并以入口回归确认实际路由缺陷。没有为了方便恢复直接改用户数据库。

## 实现边界

- 在共创流程到达正式核查前，缺少可用候选时派给独立 `title` 专家；只给绑定正文和角色方法，不能读取其他评审对话、写正文、替用户确认。通过 `submit_publication_candidates` 保存后立即等用户决定。
- 程序校验单行标题、正文版本、候选重复与首段误用；这是结构/来源边界，不等于自动证明标题好坏。
- 识别新 `publication_selection` 及旧版精确等待原因，旧项目无需重新填写材料。界面展示当前有效批次；旧批次部分无效时整体待重新拟题，不通过过滤后重排编号造成误选。
- 两个输入入口都接受自然语言标题讨论，包括无“标题”关键词的“换一批”。讨论不确认、不改正文、不进入事实核查。
- 明确的“就用第二个吧”“第二个就行”等可确认真实候选；否定、疑问、附带修改与越界编号不能授权。复杂或模糊表达仍可先讨论，不要求用固定口令交流。
- 明确要求重新拟题时，必须保存真实候选，不能用普通文字冒充完成。保留工具错误后的修正机会，不通过隐藏回复工具造成不可恢复的未授权工具错误。
- 标题卡不再用“缺少材料”“补齐信息”描述此环节。成功提交后清空输入，修改输入时清除旧错误。小窗口主输入框占据真实布局空间，避免覆盖标题卡按钮。
- 原有自主写作路径未做全量重构；事实门禁、用户选择授权与正文版本绑定未放宽。

**内容质量边界：** 最终三个候选已是简短标题，但其中一个候选“往往走得越远”与其理由中的“走不远”有语义矛盾，其他候选也有概括偏强的风险。本次不把候选保存成功当成标题质量或事实审核通过，未自动选中这些内容。用户可以继续指出矛盾要求改拟；自动识别所有语义矛盾不在本轮已验证能力内。
