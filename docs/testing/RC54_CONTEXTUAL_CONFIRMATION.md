# rc.54 对话语义确认与阶段交接

日期：2026-09-28。代码基线：`25ca1d3`。本次修复不代表整套产品已通过最终用户验收。

## 真实故障与根因

对用户截图对应的本机事件只读核对：原写作任务停在 `review_reader → central_revision`，作者连续发出“认同”“认可；”后，系统另开普通讨论轮次，原任务仍为 `waiting_user / CO_CREATION_CHECKPOINT`。不是模型服务拒绝，也不是用户没表达清楚。

存在三层错误约束：

1. Bridge 根据固定认可短语决定进入讨论还是恢复写作，“认同”和带分号的“认可；”均未命中。
2. `resumeDraft` 再做同样的短语校验，即使模型理解了也不能交接。
3. 讨论回复末尾强制再次询问是否认可，形成反复确认。

提纲另有子串判定问题：“不同意”含“同意”，可能被错误放行。修复前已用原函数做红色复现。

## 新契约

**模型理解本轮话语与上下文；程序负责精确状态、来源、版本和权限。**

- 新增 `interpret_author_reply`，使用当前待回答问题、已展示成果和近期交流判断意图。由现有 AgentRuntime 统一记录、调用和取消，不在工具里嵌套隐藏模型请求。
- 意图结果绑定本轮原文、会话、待确认事件、正文和简报版本；不让模型自己选择待恢复的 run ID。
- 明确认可恢复同一写作任务；修改当前提纲/正文先返工；异议、追问、部分认可留在当前专家。
- 较新的反对消息、检查点变化、正文或简报变化都会使旧确认凭据失效，不能拿以前的“认可”继续执行。
- 认可的交接回执在意图保存后立即由程序保存，不再要求模型重复说一段固定话或调用第二次确认工具。
- 提纲和其他阶段的返工决定不能被导演直接当作下一阶段授权。共创模式逐位专家确认继续保留。

## 同类入口审计

| 入口 | 本次处理 | 保留的边界 |
|---|---|---|
| 写作方向确认 | 不再以固定短句白名单确认或作废方案 | 确认与更改方向不能混作原方案确认；绑定方案版本 |
| 提纲、初稿、每位审校的确认 | 统一上下文意图与同任务交接 | 追问、否定、返工不跳过；每个检查点单独授权 |
| 标题候选选择、重新拟题 | 语义定位候选；自然反对可重拟 | 多个候选只有笼统“都不错”时必须澄清，不能代选；绑定正文/候选版本 |
| 配图策划与确认 | 取消特定确认口令 | 只保存策划，不生成图片、不购买服务 |
| 重新核查、完整写作 | 通过语义区分执行要求和解释问题 | 事实门禁及正文写入权限不变 |
| 补充材料后的继续 | 不再因回答短就直接拒绝进入评估 | 材料是否充分仍由现有 readiness 评估，空消息不放行 |
| 跨文章写作偏好 | 自然语言记住/忘记，保存原始作者话语与意图凭据 | 普通改稿反馈不是长期授权；不扩大权限/材料可信度；只软清除本项目偏好 |

仍保留的匹配不是“确认口令”：内部 stage/工具枚举、版本与来源原文绑定、删除项目名称核对、显式网络地址授权。旧标题和偏好直接 API 仍兼容旧格式，但桌面主对话先走语义解释，不依赖它们放行。无等待检查点时保留老客户端的“开始”快捷入口，其余自然说法仍走语义入口，不是拒绝名单。

亲历材料、风格引用以及自主/共创的来源授权函数仍保留保守来源核验。本次没有将它们扩展为仅凭模型推断即可提高材料可信度或更改长期授权；不宣称所有业务授权规则都已语义化。

- MiniMax 对不适用的 nullable 字段可能直接省略；将仅标题选择需要的 `selectionIndex` 改为可选，程序归一化为空，不靠增加调用上限。

- 所有真实验证只写 TEMP 合成/备份工作区，未自动放行核查、未修改原项目。
