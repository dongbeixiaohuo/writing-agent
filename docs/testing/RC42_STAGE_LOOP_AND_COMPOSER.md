# rc.42：语言润色重复生成与主输入框性能

## 现场结论

读取用户正在使用的 rc.41 工作区（只读）。目标 run 为 `e16bcf13-d05d-4612-8cdf-57b26c3d6c2b`，用户随后已停止。该任务跨多个执行段的累计请求数不能当成本次重复次数；本次确认语言终审连续 11 次保存失败，均为 `BODY_STAGE_CONTAINS_PROCESS_NOTES`。

原因链：

1. 集中修订把正文与末尾加粗的“改动说明（三处）”一起保存；旧校验只检查开头，漏掉长文后记。
2. 绑定版本长 1,542 字符，末尾说明占了很大部分。润色返回约 789 字符正文且遗漏 Markdown 标题。旧校验以带说明的全文为长度基线，把正常去除说明也算成大幅删减；标题缺失与流程说明共用同一错误码，反馈不准确。
3. 保存失败会要求同一专家重新输出，但没有单阶段相同失败检测，因而在整个执行段大额度内反复生成。

此样例有模型内容返回，问题在本地提交契约、校验与恢复循环，不归因于 MiniMax 访问故障。

## 修改

- 正文阶段拒绝明确的 Markdown/加粗流程后记。对历史污染版本仅派生纯正文比较基线，不静默修改旧版本、不自动删改用户正文。
- 润色保留 Markdown 标题及正文长度约束；区分 `BODY_STAGE_STRUCTURE_MISMATCH` 与流程说明，返回具体必需标题和长度。普通第一段不再当成锁定标题逐字比较。
- 实际专家上下文加入程序产生的正文交付契约，优先于导演任务说明中的“返回版本号/改动报告”等矛盾格式建议；保留所有原始输入数据。
- 同一分派内：同码同内容再次失败即暂停；不同无效结果累计三次也暂停。不是提高请求上限，也不跳过校验保存残稿。
- `STAGE_OUTPUT_NOT_SAVED` 持久化为可恢复暂停，记录校验码与次数；主对话和运行记录不误报网络、额度或结果未知。只有作者主动重试才再次调用，保留原分派与已保存阶段；恢复可重新核对版本，不重做研究/提纲/正文。
- 历史 Markdown 使用按内容缓存的 React 组件，新片段不会触发全文历史重新解析；主输入框文字留在 DOM/ref，React 仅维护空白/可发送标志。补充原生 `isComposing` 与 229 键码检查，避免输入法确认被当成发送。
