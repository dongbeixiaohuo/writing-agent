# rc.13：澄清回复保存失败定向修复

日期：2026-09-21。范围为普通对话形成写作方案时的持久化可靠性和错误提示，不代表完整产品或最终用户验收通过。

## 现场证据与根因

只读检查用户当前工作区的最新失败运行 `c0888b2c-fdb1-4ad9-83b5-081464d12519`，发生于北京时间 2026-09-21 00:39:56–00:40:14，用途为 `writing-pack:intake`。

- 用户已通过 5 轮自然对话表达主题、心理分析角度、平台、篇幅和案例写法。
- 两次 `respond_writing_intake` 都因 `INTAKE_SOURCE_QUOTE_INVALID` 被拒绝，随后达到内部工具调用上限；实际共 3 次模型请求、2 次工具调用。
- 模型把用户原文的 ASCII 双引号改成中文弯引号，触发了逐字引用校验。原始用户消息已有持久材料与版本来源，却又要求模型复制一遍作为保存方案的条件，是多余且脆弱的工程契约。
- 原返回内容还暴露第二个问题：用“我替你做的判断，你看看要不要调整”自然表达假设，未命中固定的“建议/暂定”等关键词，也会被 `INTAKE_ASSUMPTION_DISCLOSURE_REQUIRED` 拒绝。这应由产品稳定标识，不应要求模型说暗号。

不是用户输入问题，也不是服务商额度不足。本次没有提高预算或移除循环保护。

## 修改

1. 普通方案来源由程序根据已持久化的用户材料、版本和事件绑定。工具版本升至 `3.1.0`，`sourceQuotes` 仅作为可选旧格式兼容字段，不作为来源或授权；不再要求模型复制用户原文。
2. 方案由程序统一显示“待你确认的写作方案（尚未开始写作）”，稳定摘要明确列出建议或暂定项。未确认不会开始正文写作。
3. 亲历材料、风格参考、自动推进等授权仍要求完整原始用户消息及正确材料/版本绑定；未降低这些门禁，也不允许模型自称已获授权。
4. 主对话把 `respond_writing_intake` 显示为“整理本轮回复”。历史失败与停止卡片可按持久错误码说明实际原因，不再只有“写作工具失败/运行保护”；只展示允许列表里的安全解释，不输出原始内部错误内容。
5. 原项目、原始消息和失败运行历史不改写。此次只读生产数据，所有重放在独立工作区完成。

代码入口：`packages/application/src/conversation-intake.ts`、`packages/client-bridge/src/application-bridge.ts`。
