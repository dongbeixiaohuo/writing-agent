# 按职责投影 Agent 上下文

2026-10-05。第一轮通用投影只改变请求组装，不修改历史稿件、证据台账、确认回执或事实门禁，不新增总结上下文的模型调用。同日追加的事实核查改为“成稿提取 → 逐条验证”两段，增加一轮提取请求，换取后续搜索请求不再反复带入全文与全部台账；见下文。

## 规则

| 角色 | 默认产物输入 | 按需读取 |
| --- | --- | --- |
| 导演 | 正文/提纲版本目录、标题层级，证据数量/编号/研究缺口，完整必要审校与返工信息 | 当前绑定版本的完整正文和证据 |
| 提纲、主笔、集中修订 | 完整绑定正文/提纲；证据按列无损表示，保留每条主张、引文、来源、使用边界与未核实状态 | 授权原始材料 |
| 编辑/发布/读者审校、语言润色、标题 | 完整绑定正文；全部证据主张与限制，默认不附整份原始引文 | 精确引用/来源有疑问时读取绑定证据版本 |
| 事实提取 | 完整当前成稿、已选发布标题及可选配文；证据仅编号/主张索引 | 这一轮只提取实际出现的事实，不判定是否受支持 |
| 事实验证 | 提取的主张、对应成稿原句；所选证据的全部引文、来源与限定 | 其他证据、成稿上下文、已有搜索结果与来源原文 |

`claimFields` 是证据列名，`claimRows` 的每行按该顺序取值。省去重复字段名，不按关键词选事实，不截断文章或事实限定。未知旧格式保留原文。此表示仅存在于请求层，提交工具仍按原有对象 schema 校验。

修订讨论保留每条用户发言的角色、顺序和原话。只有与本次已提供的完整材料逐字相同的文本才改为材料版本引用；助手旧报告保留序号，最近两条助手说明默认保留。`read_review_discussion` 可取回绑定项目/会话里的原始条目；独立审校不获得这个工具，不能借此窥读其他审校意见。正文更新后的晚期导演上下文不重放旧审校讨论。

已省略字段不算已提供全文：用户/专家主动读取完整证据时，工具结果不能被替换成指向精简目录的假引用，而是返回保留所有值的证据表。完整正文的必需读取保留全文。版本变化、未知版本和失败结果也不能被去重。

旧数据把第三方文章和作者要求都存成 `pasted_text`，单凭文本长度或 `intake-user-` ID 无法可靠区分。本轮不会粗暴移除这些内容；只消除已证明重复的副本。原始素材与台账之间的进一步语义去重仍需要可靠的材料用途标注。

## 最终事实核查的两段契约

1. `prepare_fact_check` 只接收成稿中确实出现的可核实主张、连续原句、位置与匹配证据编号。原句不在当前正文、已选标题或已选配文中则拒绝；未选择配文不构成缺料。普通感受、比喻、文风不生成核查问题。
2. 提取结果由工具完成事件持久化，绑定正文、证据和发布选择版本。恢复同一版本可复用；任何绑定变化都必须重新提取。切换到验证阶段时清空旧模型对话，而不是删除运行记录。
3. 验证请求不重复发送正文全文、未使用证据原文或旧作者/助手对话。选中证据保留全部值，包括精确引用与使用边界；索引不是证据，不能把未提供内容假定为支持。
4. 搜索结果与来源全文保留在 SQLite。模型续轮只携带来源定位和短摘录；需要相关上下文时用 `read_fact_record` 本地分页回读（单次最多4000字符），不再联网、不占搜索次数。`read_fact_article` 与 `read_fact_evidence` 同样可按需补读。返工后的新验证阶段获得 `savedSourceRecords` 目录，因此历史模型对话清空后仍可复用本轮旧来源。
5. 一整个写作运行最多6次不同事实搜索尝试，包含失败；返工或重建运行时不重置计数。相同查询命中缓存不新增尝试。额度用尽后不再向模型提供搜索工具，仍可读取已有结果；不能把未验证条目改成通过。
6. 最终提交必须覆盖已提取的全部编号和主张，不允许删除未证实条目来制造通过。结论仍由原有事实门禁计算；保存后直接展示逐条核查摘要，不再请求一轮仅用于说“已完成”的模型回复。

代表性模拟使用一条实际成稿事实、6000余字符正文、未入正文的约28000字符长引文和数万字符搜索返回。验证续轮没有正文重复或未使用引文，搜索结果投影小于3000字符；一轮搜索，三次模型请求（提取、检索、验证保存）。这是确定性模拟，不是真实 MiniMax 耗时或事实准确率结论。
