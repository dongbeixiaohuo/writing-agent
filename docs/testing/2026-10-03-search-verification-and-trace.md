# 搜索连接验证、超时拆分与跨天运行轨迹

## 范围与结论

本次修改针对运行记录日期、搜索路由诊断、Tavily/Parallel 连接验证和检索次数控制。修改在本地开发分支，尚未生成新安装包、发布或修改用户已安装版本。验证未改写真实项目或真实搜索配置；凭据通过现有凭据管理器读取，不进入日志。

### 原问题取证

- 当前真实设置为 Tavily 开启、Parallel 关闭。
- 2026-10-03 11:04:14—11:04:34（Asia/Shanghai）的真实 `search_fact_sources` 记录耗时约 20 秒，返回 `SEARCH_TIMEOUT`，但没有服务分派记录。仅凭旧事件不能判定 Tavily 是否实际收到 HTTP 请求，更不能断定 Key 错误或 Tavily 故障。
- 确定性复现了两个程序问题：授权等待消耗网络总时限，可导致授权后完全没发请求；双服务启用时，Parallel 多次握手可耗尽总时限，导致已启用的 Tavily 得不到回退机会。

## 修改后的逻辑

1. 事实核查专家先区分客观事实与感受、比喻。已有证据足够时不必搜索，不为文风或措辞偏好制造事实问题。
2. 需要外部证据时，提交简短公开查询，不发送整篇文章。桌面端展示原样检索词和目标服务，由用户同意后外发。等待授权最多 120 秒，与网络计时分开；拒绝、授权窗口异常、授权超时都会明确记录“尚未调用搜索服务”。
3. 只启用 Tavily 时直接调用 Tavily；只启用 Parallel 时只调用 Parallel。都启用时 Parallel 优先，失败才回退 Tavily；不擅自启用未选服务。
4. 单次检索联网整体最多 20 秒，每个 HTTP 交换（包括读响应体）最多 8 秒。双服务按剩余时间分配预算，确保 Tavily 有实际尝试机会。停止会中止本地等待，不再启动新回退；已经发出的请求是否计费由服务商决定。
5. 每个运行最多 6 次检索尝试，失败计入。相同查询按“运行 + 开关路由 + 查询文本”缓存，恢复同一运行后仍沿用已消耗次数与结果，不通过重建运行时重置额度。新建一次核查运行重新计算，不是整篇文章终身最多 6 次。
6. Tavily 固定 `search_depth: basic`、`max_results: 5`，关闭自动参数、生成答案和原始全文；最多每运行 6 次 Tavily 搜索请求。Parallel 一次逻辑搜索包含 MCP 初始化、初始化通知和一次搜索工具调用，不能把这 3 次 HTTP 都算成 3 次搜索。
7. 来源原文阅读由 `read_fact_source` 单独执行：只能读本轮发现或证据账本登记的 URL，执行网络安全策略，单次最长 20 秒，同时受该运行总工具调用预算约束。这部分不是新的 Tavily 搜索请求。
8. 模型结合原始来源、日期、摘录和当前稿件给结论；搜索成功不等于事实通过，搜不到不等于事实错误。外部搜索不可用时明确未联网验证，保留无法证实或错误的主张，不伪造证据，也不取消交付门禁。

## 用户可见变化

- 时间线显示本机当地完整日期和时间，标明“较早在上 ↓ 最新在下”，给最新行加标记并提供跳转按钮。
- 搜索步骤记录等待授权、读取凭据、实际发出的服务/HTTP 次数、耗时、失败代码和回退情况。详情保留带时间的过程记录，即便未得到最终结果也能看到停在哪一步；打开的搜索详情随阶段进展更新。
- 设置增加两个独立“验证连接”按钮，保存配置后自动验证已开启服务（新填 Tavily Key 也会验证）。测试各服务自身，不通过备用服务冒充成功。
- 固定公开测试查询为“中华人民共和国成立日期 1949年10月1日”。Tavily 每次验证有一次 basic 查询用量，界面明确提示。
- Key 已保存不等于连接可用。只有成功收到有效搜索协议响应才显示绿色“已验证可用”，附验证日期/时间；失败、改配置或重启应用后不沿用旧绿色标记。开关表示是否启用，绿色表示最近一次验证状态，两者分开。
