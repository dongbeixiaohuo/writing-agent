## 实现

1. 对写作简报已授权的小材料直接提供全文：单份不超过 6,000 个 Unicode 字符、每次内联合计不超过 12,000。超出的材料继续走已有分段读取，不截断后声称已完整提供。
2. 只有实际已派发、已保存的请求能证明内联材料已提供；同时校验项目、材料版本、全文、范围和信任标签。保持 `instructionAuthority=none`，不注入本地源文件路径。
3. 导演可在 `director_decide` 的 `readinessReason` 中同时给出充分性判断并派发当前下一阶段。仍使用原有材料读取、当前版本、阶段顺序、作者确认和事实门禁；有缺口仍须提问。旧的独立充分性工具保留兼容。
4. 没有绑定产物时不提供产物读取工具，避免研究专家误用材料版本 ID。
5. 交接说明建议 200 字；提纲按正文目标的 40% 给出参考篇幅（200–1,600 字）；研究备注按正文目标的 20%（100–600 字）。只聚焦正文实际需要的事实和边界，不逐句转录材料。它们均为模型写作目标，不是保存硬限制，不截断内容；重要风险、作者要求的细节仍须保留。
6. 材料改为手动选择的参考节选，默认收起，明确不是进度；去掉重复文本和裸链接预览。专家接手后清除上一个请求的任务说明，最终成果仍真实流式显示。
7. 记录首/末推理活动时间和次数，与响应头、首/末有效内容、总耗时分开呈现。仅记录活动元数据，不保存或展示私有推理；旧记录不补造数据。

### 实现范围

- 研究提示词按任务范围取舍：指定材料的改写/解读先整理直接支持的事实、引句、缺口；多来源冲突和影响文章前提的风险仍需处理。当前研究没有外部搜索工具，明确说明未进行外部核验，不能臆造搜索结果。关键缺口仍提前暂停，不留到成稿后补救。开头、结尾、标题、提纲留给对应阶段；明确排除的材料只记必要理由和风险。
- `submit_writing_stage` 的研究 `content` 支持直接提交 `{sources, claims, notes}` 对象。来源只声明一次，条目通过 `source_id` 引用；未提供的 `evidence_id` 由程序分配，不与明确提供的编号冲突。程序不会代替模型填充 reliability、verification_status、source_quote 或 use_boundary。
- 新模块 `research-evidence.ts` 先校验压缩格式，再展开为原有平铺账本，并继续调用原 `parseEvidenceLedger`。未知/重复来源、重复证据号、缺少必要字段、非 illustrative 空引句、不合法链接仍拒绝；允许 HTTP 与 HTTPS。原有平铺 JSON 字符串保持兼容，无需迁移历史项目。展开也受原 100 万字符容量边界约束，超限拒绝、不截断，避免共享来源造成输出放大。
- 非研究阶段仍只能保存字符串成果；阶段顺序、版本绑定、读材料门禁、确认检查点和最终事实门禁没有绕过。
- 新对象格式的公开 `notes` 支持分片流式预览，仍隐藏原始证据 JSON、嵌套元数据和私有推理，不把过程预览保存成最终回复。
- 专家提示不再重复导演专用的调度参数说明。只去掉与当前简报程序生成摘要完全一致的回显，或完全一致且带固定交接前缀的回显；额外修改、建议/暂定项、历史不同方向仍保留。原始指令与最新指令完全相同时不再重复注入。去重不参与认可语义判断，不改变用户输入或运行历史。
