# rc.31：前置沟通、核查问题归属与确定性收尾

日期：2026-09-24。专项修复可进入桌面复测，不代表整体验收通过。

## 根因和修改

- `readyRunIds` 和协作层执行段事件查询把一次 ready 用于后续所有阶段。改为同一真实状态源，绑定下一阶段、简报、正文、标题、证据、授权材料版本、阶段标记和返工标记。
- 每阶段先核对输入和上阶段结果。完整同版本材料继续复用缓存；后续专家接收精确绑定的成果，恢复入口的显式读取要求不变。
- 原 `pauseAfterTool` 将全部失败核查直接改为要求作者补来源/授权删改。删除该自动归责：反馈回导演，由其判断内部修订、复核或作者信息需求，最终导出仍按原门禁。
- 区分普通比喻/创作性化用与真实引用；不得用“文学文体”豁免错误引文。可选润色不是必答信息。
- Agent 工作或已在提问时，主对话不重复展示红色核查归责卡片。旧核查及历史问题保留，详情和导出限制没有删除。
- 真实模型发现导演 finish 后仍重复请求/重复 finish。补充应用层 `completeAfterTool`：持久 finish 且所有阶段/当前事实门禁通过才结束，不再追加模型确认。
- 无显式限制的完整写作默认与桌面一致（64 请求/96 工具）；用户/调用者明确指定的限制不提高。通用 Runtime、intake、fact-only 的默认限制不变。
