## 改动与边界

1. 显式继续写作时，用持久化 run.resumed 基线计算本执行段调用量；模型、工具、重大返工保护按本段计数，历史调用和 Token 仍累计保存。自动重试、自动专家切换不刷新该基线，原固定保护阈值不提高。
2. 旧 budget_exhausted 写作任务可显示“继续未完成步骤”，也可结束本轮。不要求重新确认标题，不重做已保存研究/正文；没有新增作者意见的恢复保留未完成专家分派。需要重新核对已保存输入时，允许只读检查。
3. 状态和主张类型枚举复用 writing-core 的 schema。明确部分支持/缺证/引用类型的正确字段；不把不确定值转换成已支持，不新增“有条件通过”。运行时提供实际有效的 validEvidenceIds；notes 中的编号不冒充已登记证据。
4. 格式纠错按专家任务上下文独立计数，最多两次纠错。强调重新提交完整参数，不提交差异补丁。未开放工具整批不执行，并给出当前允许列表与有限修复机会；授权和阶段检查不放宽。
5. 真实重放发现模型可连续只用普通文字声称“提交核查”，并未调用工具。对尚未完成的导演/研究/标题/事实核查请求设置 toolChoice=required；公开文本阶段仍可先正常流式展示，需持久化时下一请求要求工具调用。自然语言“已完成”不能改变持久状态。
6. 运行记录显示本执行段模型/工具调用与任务累计 Token；详细历史仍完整保留。
