# rc.37：模型设置与旧项目切换

日期：2026-09-25。范围仅限模型设置、配置保存和切换，不修改写作专家、事实门禁、阶段顺序或原项目数据。

## 原因与实现

- 原 Host 将全工作区 `waiting_user` 视为运行中，导致旧项目等待确认时也无法保存模型配置。现在仅阻止仍执行中的 queued/running/paused；等待作者确认的阶段不受影响。
- 原切换创建新 bridge 时重置 generation/revision，并丢失所选 session。前端会拒收“比当前旧”的快照。现在保留项目及会话，使用递增 generation，后续恢复使用当前模型。
- 原设置只有一份配置，每次修改必须重新填写 Key。新增 schemaVersion 3 供应商目录，每个供应商维护自己的模型列表；只有当前选择用于下一次请求。
- 老 v1/v2 配置只读加载，不自动改端点或 Key；保存时升级。同一协议与规范化地址允许留空沿用 Key。新供应商/改端点必须输入新 Key，且新凭据使用独立引用。
- 按参考截图采用供应商列表、编辑/添加、预置/自定义分栏、折叠高级设置、模型目录。主对话底部模型名称可直接点击进入设置。不加入截图中无关的插件、Agent 预设、Bedrock 等未实现能力。
- “获取可用模型”由 Host 发送目录请求，禁止重定向，有时长与体积上限；不支持目录时可手动输入。目录存在不是工具调用验证。
