## 本次变化

- PRD F02 明确导演决策、独立上下文、串行评审也必须隔离、材料不足即时提问；WA-010 重新打开，WA-018 增加 F01/F02 和 CR-002 业务场景作为签收前提。
- 新增 `assess_writing_readiness`。每个执行段的写作提交必须先 ready；必要材料和恢复上下文未读取，ready 会被拒绝。
- 任意阶段可报告 needs_input，最多两问。问题持久化到 `run.waiting_user`，停止同一模型响应中的后续工具，不创建缺料占位正文。
- 恢复需要非空、非纯确认式回答；问题/答复从持久事件重建，仍按未核实的用户信息处理。回答不足可继续等待，不能凭点击继续就放行。
- 恢复时保留原始写作目标；材料读取按当前版本和最新执行段检查连续完整分页，不能用以前的读取或只读一页放行。现稿基线随新运行的 run.started 原子持久化，跨首次等待前崩溃、后续等待、恢复、中断和再次恢复保存，仅成功提交新 draft 后解除。
- Bridge v18 将问题直接投影至主对话；输入框可回答并恢复原 run。新执行状态出现在本次答复下面，避免只更新已滚出屏幕的旧状态行。
- 桌面安全错误映射保留“需补充信息”的可解释错误码，不泄漏内部内容。专项事实核查保持原有正文/证据读取合同，不被写作 readiness 意外阻挡。
- `independentReview` 能力元数据更正为 `migrated_not_isolated`，没有把本次交互基础称为真正独立合作。
