# DSH 前端源码复用与写作化实施方案

文档版本：1.1 · 2026-09-16 · 关联变更：CR-001。目标产品仍为 Writing Agent 1.0。

配套：[PRD](../prd/WRITING_AGENT_1_0_PRD.md)、[运行时契约](RUNTIME_CONTRACTS.md)、[任务清单](BACKLOG.json)、[源码基线](../research/SOURCE_BASELINE.md)。本文件是待实施契约，未构建或运行前端，不包含已经通过的视觉测试。

## 1. 已确定的决定，不重新讨论

用户明确选择：**直接利用 DSH 前端源码、页面结构、视觉体系和交互做新版本，避免从零承担 UI 设计，并让后续界面调整集中、可控。**

这不是“参考 DSH 风格重新设计”，不是“在旧桌面界面上换皮”，也不是“给 DSH 安装一个写作插件”。新前端和自有 runtime 都由 `dongbeixiaohuo/writing-agent` 的源码及构建产物负责。来源复用不等于运行时依赖外部 DSH 宿主。

旧 `writing-agent-app` 0.1.0 保留历史与必要兼容说明；它的数据库、文章、模型配置格式可作为迁移输入，但 App.tsx、全局样式、页面组织、Tauri 启动链不作为新版 UI 或应用壳基线。新版本无需安装或启动旧应用即可导入受支持的数据。

**实施顺序：移植原版界面基础 → 完成自有服务适配 → 加入写作面板 → 根据真实反馈调整主题与布局。** 不先重设计，不为了减少几个依赖把已选 UI 全部重写。

## 2. 核对到的上游事实与限制

本次 GitHub 读取的固定 commit 为 `0d1f50007f9bca3f52b06e1c3074fa14d5fb0720`，前端模块地图为 `packages/client/README.md`。[S13]

DSH 前端不是独立静态页面集合。官方文档描述它由浏览器侧 Cordis 应用、Client Modules、API Gateway、Slot 与 Conversation 组成；Host 拥有权威状态，Client model 做镜像，UI adapter 和展示层消费这些状态。[S14] 因此移植必须覆盖所选页面的依赖闭包、必要 Host 接口和类型/构建步骤，不能只复制 `.tsx` 后更换 API 地址。

主题模块提供 light/dark/system、主题快照和 `--dsw-*` 等设计变量；第三方主题可通过别名变量覆盖。它提供的是可扩展基础，不是本产品已经完成的主题编辑器。[S15]

右侧文档预览支持多种只读展示，但官方明确“Preview, not editing”。稿件编辑、锁定段落、接受差异和版本保护需要本项目新增；不能以预览器已经能看 Markdown 为由宣称编辑完成。[S16]

DSH 自身的桌面应用是承载同一 Web UI 的 Electron 壳，带有自身的运行时、协议和分发流程。[S17] 这是可供源码移植的候选，不意味着用户已指定 Electron，更不意味着应复制上游账户、更新服务器和完整插件安装流程。

## 3. 前端移植范围与裁剪表

以下是读取到的上游路径或组名，不代表整个组可以直接单文件复制。每行都要在 `FRONTEND_UPSTREAM_MAP.md` 中列具体源文件、依赖、目标位置、差异、许可和测试。

| 上游范围 | 本版处理 | 验收要求 |
|---|---|---|
| `client/web`、`modules`、`ui-renderer`、`ui-slots` | 移植所选 UI 必须的启动与组合闭包 | 页面独立本地启动，不依赖外部 DSH server；禁止运行时拉取上游页面代码 |
| `ui-layout`、`ui-dockkit`、`ui-sidebar`、`ui-sidebar-right` | 保留导航、布局及面板组合方式 | 原布局可用；写作面板通过现有扩展位置接入 |
| `ui-theme`、`ui-primitives`、`locale` | 直接移植主题、基础组件、适用资源与文案结构 | 明/暗/系统主题及基础控件正常；自定义集中管理 |
| `ui-conversation`、`ui-chat`、`ui-session`、`ui-tool` | 保留对话、输入、执行展示与会话绑定 | 文本流、工具状态、停止、历史加载匹配真实自有事件 |
| `ui-workspace`、`ui-model-selection`、`ui-settings` 及所需设置包 | 移植配置与选择界面，适配本项目语义 | 指向自有模型配置/工作区，不冒充官方套餐授权或登录能力 |
| `resources`、`ui-sidebar-documentpreview`、`ui-deliverables` | 保留必要材料预览与文件呈现；限制不必要格式 | 稿件由领域 ArtifactVersion 加载；只读预览不成为直接文件写入通道 |
| `client/connection`、`store`，所需 `api` 与 `host` 模块 | 一并审计必要通信、Client model、生成类型与构建链 | snapshot/stream/cancel/reconnect 经实际测试；不留下旧后端隐式依赖 |
| `ui-brand-official` | 不启用官方品牌模块；用自有品牌模块填充同类入口 | 名称、Logo、页面标题、About/反馈入口为 Writing Agent；法律署名仍保留 |
| 代码终端、任意执行、完整插件管理、调度等非首发能力 | 不默认挂载；只保留真正必要的依赖 | 删除入口不能使依赖树启动失败；隐藏按钮不等于后端权限已关闭 |
| `apps/desktop` 及所需 desktop host | M3 默认优先评估源码移植最小壳 | 启动本项目 runtime、同源 UI、自有路径和安全桥接，不启动外部 dsh |

“直接复用 UI”指保留可用界面基础与交互，不强制保留与写作无关的全部工具，也不允许删到只剩几个按钮再宣称完成。裁剪按功能与依赖分别记录，不猜目录名直接批量删除。

## 4. 目标模块与改动位置

以下为本项目目标模块，不宣称它们是上游已存在的 API。实际目录可在 M0 调整并记录映射；每个逻辑模块不必都是独立 npm 包。

```text
packages/ui/                  DSH 派生基础，尽量保留上游模块边界
  shell/                      布局、导航、会话、设置组合
  primitives/                 共享控件与内容展示
  theme/                      原主题与集中覆盖
  brand/                      Writing Agent 名称、标识、帮助入口
packages/client-bridge/       自有服务到 Client model/Remote 的边界
packages/writing-ui/          稿件、证据、版本/修订、核查/导出面板
apps/web/                     自有 Host、构建与本地启动
apps/desktop/                 新桌面容器，共用上述 UI/runtime
writing-agent-app/            legacy，不进入新应用依赖闭包
```

为了方便后续调整，明确四类改动入口：

| 要改什么 | 修改入口 | 不应该修改 |
|---|---|---|
| 颜色、字号、间距、圆角等 | 集中主题变量/别名及覆盖样式 | agent loop、事实门禁、每个页面散落的硬编码 |
| 名称、Logo、About 和帮助入口 | 独立品牌模块与文案资源 | 上游版权声明、数据库实体或模型请求 |
| 左右区域、面板显示与默认组合 | shell 的布局配置/Slot 注册 | 全部业务页面重写；在核心循环中写布局条件 |
| 新增写作能力页面 | writing-ui 新模块，消费 bridge | 修改所有对话组件、在浏览器复制一套写作状态机 |

上游已有的 CSS token 名、内部标识或来源注释可以保留。不为“去 DSH 字样”大规模改名，避免破坏依赖、样式及后续补丁映射。用户可见品牌、实际启动/网络配置与法律署名要分别处理。

## 5. 先建立保真基线，再扩展写作

### 5.1 基线 U0

在固定源码版本与合法可用构建环境中，先记录原版 DSH 的关键界面与交互，再建立移植版的同内容参考。上游参考环境仅用于开发比较，隔离测试目录、假数据和凭据；不得把上游参考进程或产物当成新产品运行条件或加入发行包。

至少记录：空工作区、项目/会话导航、普通对话和输入、工具执行中、设置与模型配置、侧栏文档预览。默认以 1440×900 和 1280×800 视口、明/暗主题建立测试夹具；分辨率是测试建议，不是额外移动端承诺。

同一操作系统、浏览器/容器、字体环境、缩放与固定内容下比较。时间戳、动态 token 和授权品牌差异可显式遮罩，其余差异逐项审核；不能整块遮罩关键 UI 让测试通过。视觉比较之外还要测试键盘焦点、输入、滚动、菜单、缩放/面板收放及长中文段落。

可接受差异：Writing Agent 品牌与文案、经过评审的非写作能力裁剪、安全限制、写作功能扩展。不可接受差异：未经授权更改整体设计、混入旧 UI、大面积布局/字体/交互退化。

如果暂时不能运行上游参考，记录缺少的具体构建环境并继续可执行的源码工作；视觉基线标 `BLOCKED_EXTERNAL`，不得用生成图片或自行绘制效果图替代源码运行截图。

### 5.2 M1 允许的本地 mock

WA-023 可使用桥接接口上的确定性本地 mock，使 UI 先独立运行；页面显著标识“界面移植预览，未接入真实写作”。mock 数据只用于测试，不能写入用户正式项目、报告模型 token 或核查通过。

M2 / WA-011 必须替换为真实 Application Service。测试保留 mock 路径用于确定性回归，但正式构建默认不启用。不能因对话会动就声称自有 runtime 已接通。

## 6. 写作能力如何加入现有 UI

保留 DSH 原有对话、导航和设置体验。稿件可以在现有右侧文档/可停靠区域打开；需要更大编辑区时使用既有面板机制调整，不在首轮改变整个首页信息架构。

| 写作模块 | 放置策略 | 必须新增的行为 |
|---|---|---|
| 稿件 | 现有文档/面板区域，沿用基础控件 | 加载指定 ArtifactVersion；编辑保存、已保存状态、锁定、过期版本冲突 |
| 材料与证据 | 现有资源/右侧 tab 扩展 | 材料来源、快照时间、授权范围、证据支持范围及正文位置 |
| 版本与修订 | 现有 tab 或文档工具栏扩展 | 版本列表、修改理由、差异预览、接受/拒绝/回退 |
| 核查与交付 | 现有状态展示和独立面板 | passed/stale/blocked 与绑定快照；工作备份和正式导出区别 |
| 简报与作者确认 | 对话内卡片/现有问题交互扩展 | 明确暂定与已确认、已给授权不重复问、不可编造作者素材 |

复用 Slots 作为本项目内部组件扩展方式，不等于把本产品改成“运行在 DSH 中的插件”。新增模块与移植模块一起在本仓库构建和发行。

1.0 不做可拖拽页面设计器或在线主题市场。先提供集中配置和内部扩展范例，验证维护者日后改界面不用重写核心。

## 7. Client bridge 与状态映射

默认沿用源码移植后仍有价值的 typed Remote/Client model/Slot 架构，减少前端重写。保留必要生成器和构建脚本，精确固定普通库版本。需要替换 transport 时单独 ADR，证明可减少耦合而非把成本转嫁给每个页面。[S14]

最小映射为：

| 原前端所需能力 | 自有领域语义 | 错误边界 |
|---|---|---|
| 会话/工作区选择 | workspaceId → projectId → sessionId | 一个项目可跨会话；不得只用当前聊天 ID猜项目 |
| 提交输入 | 当前项目的 run.start/有权限的会话命令 | 不直连 provider，不绕过预算或请求快照 |
| 停止/继续 | run.cancel/run.resume | 取消迟到结果不成为正文；重连不触发 resume |
| 对话/执行历史 | 已记录 session/run 事件的展示投影 | 不把 UI 记录当权威历史，不显示虚构工具完成 |
| 稿件和编辑 | artifact.get/body.save/revision.propose/accept 的实现语义 | 带版本与 operationId，冲突不得静默覆盖 |
| 主题/设置 | 自有 settings 服务与凭据引用 | 不读取 `~/.dsh` 或旧应用目录作为运行前提 |
| 导出 | export.working_copy / export.publication | 正式交付统一门禁；不把普通文件下载伪装成核查通过 |

`artifact.get` 在此仅为查询语义示意，具体查询端点与其余命令一同写入实现契约；不得假称已经存在。所有命令输入须由后端运行时验证。

Client model 维护读模型与临时界面状态；事实核查、当前正文指针、来源归因仍由服务端提供。用户看到“已保存”必须已经成功持久提交。项目切换、旧请求迟到、流式内容、完整快照、重连补读分别验证，不能用最后响应覆盖一切。

协议握手记录 client/bridge/runtime 的兼容版本。旧静态资源配新服务时明确报错或安全刷新，不能继续使用错配 schema。发行组合统一测试，不要求以后所有内部模块永远使用同一个版本号。

## 8. 品牌、权限、网络与分发隔离

必须审计页面标题、品牌模块、图标/资源许可、欢迎与帮助入口、模型 onboarding、反馈提交、遥测、更新源、插件源、外部链接、桌面 appId/协议/安装路径/数据目录。保留法律来源声明，但不得以 DeepSeek 官方产品身份展示。

不得沿用上游默认遥测、反馈上传、更新服务或插件分发服务器。未来本项目自有更新服务须另行配置并核验；尚未实现时禁用并使用明确的手动 Release 更新指引。用户主动配置并授权的 DeepSeek 或其他模型 API，以及用户点击官方说明文档，是不同用途，不做机械域名一刀切。

自有进程不因出现 `dsh` 字符串就失败：来源注释、版权、CSS 变量、内部协议格式映射属于允许项；外部 DSH CLI/SDK 执行依赖、读取上游 home、连接已运行 DSH server 则不允许。独立性检查以真实依赖与行为为准。

DSH 的只读 HTML 预览文档描述了脚本沙箱能力。[S16] 本项目首版更保守：不执行用户/模型/网页材料中的脚本，不移植其 `allow-scripts` 行为；仍保留必要安全文档展示。这个安全差异必须纳入上游改动清单，不能被视觉保真要求覆盖。

桌面默认优先移植 DSH Electron 最小壳及必要 host/transport 思路，并替换为 Writing Agent 启动与资源路径。[S17] 保留受限渲染器边界；若采用 Electron，显式验证 `contextIsolation`、禁 renderer Node 集成、受限 preload/IPC、自定义协议路径校验、导航与外链处理。不得把 Electron 自带 Node 当成一定可以运行全部 native 模块；实际携带匹配 runtime 并验证。

桌面发行不要求复刻上游包管理、在线插件安装、自动更新或所有操作系统。仍以 Windows 自包含包为首版目标；Web 与桌面共享同一 UI 和领域契约。其他容器必须有维护者批准的 ADR，不恢复旧 Tauri 路线、不新增第二套新前端。

## 9. 上游来源、补丁与后续 UI 调整

固定 upstream commit，记录每个移植模块的原路径、文件 hash、目标路径、许可、依赖、保留/删除内容和对应测试。必要普通库可使用；从上游复制的配套库若含自有补丁，记录其具体来源，不把它当成可随意换成最新版的同名依赖。

首次引入保留源码边界，后续品牌、主题、bridge、写作扩展尽量独立提交。集中覆盖不等于绝不修改上游组件；确需修改时记录理由与关联测试，避免把维护成本藏起来。

后续同步上游采用专门 PR：对比固定 commit → 选择有关修复 → 复核依赖和许可 → 运行行为/视觉/安全测试 → 维护者决定合入。不承诺自动获得所有社区魔改；具体第三方 UI 代码的来源、许可与兼容性需要另行核查。

版权与许可随发行交付。来源登记和合法 UI 复用不等于品牌授权；不得将来源 Logo 原样当成自己的应用标识。字体/图标等资源按实际许可逐项审计，本交接包不附带任何字体文件。

## 11. Agent 不得擅自走回的路线

不能把旧 App.tsx 搬到新目录后称为 DSH 前端；不能只取配色和按钮，其余全重写；不能为了保持 UI 不改就直接连上外部 DSH 后端；不能默认继承 coding agent 的任意文件/命令权限；不能把截图相似当成写作功能通过；不能将 UI 来源决定当成未经审核同步一切上游改动的授权。

**成功标准：界面基础来自真实 DSH 源码，运行由 Writing Agent 自己控制，写作功能以清晰扩展加入，维护者以后能集中改主题、布局和面板，而不用再次从零设计。**
