# CR-003：对话优先的写作 Harness

日期：2026-09-20。状态：实施中。用户已明确：重构目标是用工程化 Harness 承载并提高 Claude Code + skill + subagent 的对话协作能力。

本补充纠正产品恢复计划中“四步引导式访谈”的解释；不能再把固定步骤表单等同于访谈。CR-002 的独立委派、缺口暂停、版本绑定、事实门禁继续有效。

## 产品交互

- 第一屏和新项目入口直接提供主对话输入框。用户可以只给一个想法、一段材料或尚未成形的问题，不以填写项目名、主题、读者、篇幅为聊天前置条件。
- Agent 从自然语言中整理目标、约束、材料与偏好；已提供的不要重复询问。缺口由当前任务决定，每轮优先问一到两个真正影响下一步的问题，允许跳过不影响推进的信息。
- 用户可以说“不确定”“你建议一下”、改变方向、补充材料和纠正理解。不得把固定问题序列包装成聊天气泡。模型建议及默认值必须作为建议呈现，不能冒充用户明确给出的事实或授权。
- 重要方向和取舍在主对话中以简短摘要确认。用户可自然回复或点击绑定当前摘要版本的“按这个方向继续”；修订摘要后旧确认无效。无需返回表单修改。
- 结构化简报是后台形成的任务状态，详细字段编辑仅作为可选高级入口。模型 API 和 Key 仍在专门设置中配置，不在写作对话中索取密钥。
- **无需学习界面才能完成主要任务。** 主对话的重要状态必须同处提供“发生了什么 → 下一步做什么 → 可直接执行的操作 → 操作结果”。不能显示“可正式导出”却要求用户自行猜测“稿件与版本”中的入口；该面板是历史追溯与精细操作的辅助入口，不是普通交付的必经路径。
- 当前版本通过事实门禁后，主对话末尾显示“导出文章”。默认推荐带排版的 HTML，也可选 TXT；桌面端弹出系统保存位置选择，成功后显示完整保存路径及“打开所在文件夹”。取消不显示成功；失败说明如何处理。核查未通过或失效时说明原因，不能以方便操作为由开放正式导出。

## 工程约束

- 澄清阶段复用现有有界运行、工具权限、请求快照、取消和事件持久化。不能绕过 runtime 直接请求 provider，也不能让澄清工具写正文。
- 原始消息、提问、已知信息、建议、摘要及确认版本持久保存；重启、切换项目后可继续。尚未明确的字段保持未知，形成可确认方案前不伪造完整简报。
- 澄清回复通过工具校验并持久提交后，本轮立即完成，不再消耗模型调用生成无业务作用的收尾。调用上限是单轮防失控保护，不是用户费用预算，也不是对话总轮数配额；不能要求用户缩小正常写作主题来规避实现缺陷。真正触发保护时，主对话明确说明是否已有回复保存、输入仍保留及下一步，保留真实失败审计。
- 首次公开回复允许普通文字流式输出；正常结束但尚未保存时，下一请求必须进入限定保存工具的模式，不能继续以自由聊天反复催促。保存指令不构成作者确认、材料或授权；预览跨保存请求保留，取消/失败后清除，持久提交前不得冒充已保存。
- 模型提出的是业务偏好，不是完整内部存储对象。材料 ID、版本号、共创模式、亲历授权和确认状态由工程层构造；禁止要求模型生成这些字段再靠反复提示纠错。仅允许无语义歧义的表示归一化（纯整数字符串、空的可选偏好）；禁止通过类型宽松化授予权限、猜测事实或接受模糊篇幅。输出仍无法校验时，主对话和运行记录给出可理解的失败说明，不裸露内部错误码或无依据要求换模型。
- 用户原文与模型生成文本保留来源区别；模型不能伪造材料原文、亲历授权或核实状态。
- 首次提出方案不等于用户确认；后续确认必须绑定当前方案和实际用户操作/答复。字段有实质修改时重新确认。
- 确认后在同一项目、会话中接入导演和专家写作，继续执行 readiness、输入版本、权限、预算及事实门禁。界面直接呈现暂停和需用户处理的问题。
- 完成标准是自由表达、针对性澄清、确认、委派、反馈修订的实际闭环；表单数量、步骤数量和工具打勾均不代表交互质量。

## 验收

| 编号 | 用户操作 | 必须观察到的行为 |
|---|---|---|
| C03-01 | 空工作区直接输入一句想法 | 自动建立可恢复对话，不弹必填向导；先交流而非立即生成全文 |
| C03-02 | 一次给出多项要求 | 保留已知要求，不再按固定顺序重复询问；只问真实缺口 |
| C03-03 | 回答“不确定，你建议一下” | 给出建议及理由，不报字段缺失错误，不虚构用户偏好 |
| C03-04 | 关软件重开，回答上一问题 | 原对话、已知要求及提问完整，接着讨论 |
| C03-05 | 看到摘要后用自然语言改方向 | 生成更新摘要；旧摘要不能被确认执行 |
| C03-06 | 确认当前摘要 | 同一项目/会话进入实际写作；首次模型自报确认不能越权启动 |
| C03-07 | 模型拟造材料或尝试直接写正文 | 工程权限拒绝；用户原文和信任标签不被改写 |
| C03-08 | 查看运行后继续反馈、修改或补料 | 主对话承载交互，详细字段面板不是必经入口；CR-002 仍成立 |
| C03-09 | 回复恰好在最后允许的调用中成功保存 | 本轮完成，不为收尾多调一次模型而误报失败；后续用户答复是独立新轮，取消/失败不得伪装完成 |
| C03-10 | 形成方案，存在未知风格或空的可选偏好 | 无须模型生成内部元数据，程序正确绑定材料及待确认状态；空偏好不阻断，权限不可由模型填入或覆盖 |
| C03-11 | 写作完成且当前版本通过核查 | 不打开“稿件与版本”，在主对话直接找到“导出文章”，选择保存位置并取得文件；显示成功路径和定位文件的操作 |
| C03-12 | 取消保存、保存失败，或保存窗口打开期间稿件/项目改变 | 不误报导出成功，不导出另一版本/项目；清楚说明取消、原因和重试入口；旧核查结果不能放行新正文 |
| C03-13 | 首条澄清仅返回普通文字，没有工具调用 | 原位流式预览；下一请求限定为保存工具，不重复自由回复耗尽上限；保存后立即结束，未确认不写正文 |
| C03-14 | 澄清从公开回复转入保存，期间停止或重开 | 保存期间不清空或倒退已显示文字；停止不提交，成功重开只有一份已保存回复 |
| C03-15 | 专家生成提纲、正文或可读审校意见 | 模型直接返回普通文本流，程序按绑定阶段原文调用保存管线；不要求模型再生成全文工具参数；真实缺口仍可追问 |
| C03-16 | 公开阶段输出被截断、取消、超时或任务/正文版本变化 | 预览不是保存，不提交残稿；schema、权限、阶段、版本 CAS、确认和事实门禁不放宽 |
| C03-17 | 专家切换时已有完整同版本材料缓存 | 注入已授权缓存并收窄重复读取工具；输入版本变化重新检查，不把重复读工具当进度；内部等待提示解释实际阶段 |

自动化测试用于状态、权限与恢复约束；真实模型和客户端自由对话体验须单独记录，不能由 mock 通过推定已达到 Claude Code 的体验水平。

## 2026-09-24 补充：逐位审校交接

共创模式下，编辑、发布（适用的模式）、读者审校必须各自提交、各自暂停。不能连续输出多份长报告后才统一索要确认。审校保持只读及独立上下文；作者对当前意见的解释、否定和调整由当前专家接住，主笔在后续修订时接收这些公开讨论和作者取舍。明确认可只允许交接下一位，不代表整稿通过或授权跳过事实核查。自主推进模式不因本变更被静默改成共创。

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| C03-18 | 共创中的单位审校专家完成 | 保存后暂停；未确认不得调用下一位；重开后保留同一等待边界 |
| C03-19 | 作者追问、反对或混合认可/修改 | 留在当前专家讨论，不改正文、不启动其他专家；ok、可以、继续等明确认可才交接 |
| C03-20 | 当前专家的公开成果或讨论 | 顶部显著展示程序绑定的专家名与职责；单一主输入框；先结论和重点，不倾倒后台字段或逐段复述 |
| C03-21 | 审校讨论只返回普通文本 | 完整 stop 后由程序调用原保存管线，一次回复即可保存；不反复催模型序列化；末尾只保留清楚的交接提问 |
